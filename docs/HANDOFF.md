## 이 시스템이 무엇인가

목동임페리얼학원(수학 전문, 국어·영어·과학 병행)의 운영 시스템입니다.

```
React 18 SPA (CRA)  →  GitHub main  →  Cloudflare Pages 자동 배포
Firestore + Cloud Functions v2 (Node 22, asia-northeast3)
경로 규칙: artifacts/{APP_ID}/public/data/{collection}
APP_ID = imperial-clinic-v1
```

원장이 코딩 지식 없이 AI에 의존해 만들어 온 시스템입니다.
그래서 **"동작하는 것처럼 보이지만 실제로는 끊겨 있는 곳"이 많습니다.**
이 문서의 상당 부분이 그런 것을 찾아 고친 기록입니다.

## 반드시 지켜야 할 것

### 배포 순서

```
규칙을 넓힐 때  : firestore.rules 먼저 → 앱 나중
규칙을 좁힐 때  : 앱 먼저 → firestore.rules 나중
```

거꾸로 하면 그 사이에 기능이 죽습니다. 실제로 겪었습니다.

```bash
npx firebase deploy --only firestore:rules   # 규칙
git push origin main                          # 앱 (Cloudflare 자동 배포)
npm run test:rules                            # 규칙 테스트 89건
```

인증이 만료되면 `firebase login --reauth` 가 필요하며, **이건 원장만 할 수 있습니다.**

### 절대 하면 안 되는 것

- **`purgeStoredPasswords` 를 실행하지 마십시오.** 전 직원·학생이 최소 한 번 로그인하기
  전까지 남아 있는 평문 비밀번호가 자동 이관에 쓰입니다. 화면에 버튼은 없습니다.
- **보안 점검 보고서를 저장소에 커밋하지 마십시오.** 구체적인 침투 절차가 들어 있습니다.
- **자격증명을 대화창에 붙여넣지 마십시오.**
- `functions/.env` 는 gitignore 유지. 최상위 `.env` 는 `REACT_APP_API_URL` 뿐이라 커밋해도 됩니다.
- 온톨로지 저장소 `imperial01-create/math-ontology-data` 는 **비공개 유지**.

## 일하는 방식 (이게 성과의 대부분입니다)

### 1. 고치기 전에 실제로 확인한다

추측으로 고친 것은 거의 다 틀렸습니다. 실제로 도움이 된 것들:

- Firebase SDK를 직접 실행해 `doc(db, path, undefined)` 가 무엇을 던지는지 확인
- 빌드 산출물(`build/static/js/*`)을 grep 해서 자격증명이 실제로 노출되는지 확인
- `?debug=layout` 같은 일회용 진단 도구를 만들어 원인을 좁힘
- 순수 함수를 뽑아 node 로 돌려 계산을 검증(채점·과목 매칭·문자 생성)

### 2. 적대적 검증을 거친다

찾은 문제를 그대로 믿지 않고 **반증 단계**를 둡니다.
실제로 매번 10~30%가 반증됐습니다. 반증되지 않은 것만 보고합니다.

### 3. 판정할 수 없으면 거르지 않는다

과목·학교급을 판정하지 못할 때 **걸러내지 않고 남깁니다.**
필요한 것이 조용히 사라지는 것이, 조금 섞여 보이는 것보다 나쁩니다.
이 원칙을 어겨서 "수학 반 학생에게 내신 리포트가 한 건도 안 보이던" 버그가 났습니다.

### 4. 데이터가 없으면 없다고 쓴다

회색·빈칸·0 을 쓰지 않습니다. 사람은 그것을 '문제 없음' 또는 '나쁨' 으로 읽습니다.
글자로 "아직 기록 없음" 이라고 쓰고, **무엇을 하면 채워지는지** 함께 적습니다.

### 과목 체계 단일화 (2026-08-12)

과목이 시스템 곳곳에서 서로 다른 어휘로 다뤄지고 있었습니다. 하나로 모았습니다.

```
학원의 과목 (수학·과학·국어·영어·사회)   ← 부서 토글 · 반 · 강사가 같이 씀
        ↑ toMainSubject()
학교 교육과정 과목 (대수, 미적분 I, 수학 2-1)  ← 시험만 씀
```

**두 층은 절대 같아질 수 없습니다.** 학교가 과목을 어떻게 나눌지는 학원이 못 정합니다.
그래서 변환이 반드시 있어야 하고, 그게 **`src/utils/subjectMatch.js` 하나**입니다.
과목을 판정하는 코드를 여기 말고 다른 곳에 만들지 마십시오.

한 일:
- 부서 ID(`DEPT_MATH`)와 대과목(`수학`)이 1:1 중복이라 대과목 이름으로 통일
  (읽는 쪽이 옛 형식도 받으므로 마이그레이션 불필요)
- 부서 토글을 반·강사 과목 드롭다운에 실제로 연결 (예전에는 연결이 없었는데
  화면 문구는 연결된다고 적혀 있었습니다)
- 중등·초등 시험 표준 코드를 과목별로 분리 + 일괄 변환 도구
- 흩어져 있던 과목 비교(`subject === '영어'` 등)를 전부 매칭기로
- CSV 시간표 동기화 제거 — 과목 없는 반이 생기던 유일한 경로였습니다

### 아카데미 유니버스 (2026-08-11)

**데이터 없이 숫자를 지어내고 있었습니다.**

```js
const seed = latestScore || 70;
const pseudoRandom = (seed * (i + 7)) % 20;
```

20점 받은 학생의 학부모 화면이 '종합 70 · B등급(우수) · 예상 3등급' 으로 나왔습니다.
점수를 넣을수록 실제와 반대로 좋아 보였습니다. 이 경로를 전부 없앴습니다.

지금은 잰 것만 숫자로 내고, 절반 이상 측정해야 등급을 붙입니다.

### 1. `concept_stats` 연동 — 지금 유일하게 기능이 끊긴 곳

개념테스트를 입력해도 학부모 화면에 **영원히** 뜨지 않습니다.
저장하는 필드와 읽는 필드가 **하나도 겹치지 않습니다.**

```
저장(ExamDiagnosticInput) : latestScore / latestMaxScore / latestGrade / lastUpdatedUnit
읽기(AcademyUniverse)     : average / totalUnits / units[]
```

`docs/exam-diagnostic/PLAN.md` 의 8단계입니다.
키 어휘도 함께 정해야 합니다 — 지금 '사회' 가 양쪽 모두에 없습니다.

### 3. 수학 능력 시각화

설계 검토를 마쳤습니다(3안 + 심사). 결론:

- **첫 화면에 띄울 것은 '실력' 이 아니라 '실적' 입니다.** 진단 기록이 쌓이기 전에는
  케어 시간·클리닉 이력처럼 실제로 있는 것만 보여 줍니다.
- 내신연구소가 문항마다 **IDI 5축**(출처친숙도·변형로직·개념결합도·연산복잡도·논리전개,
  각 1~5)을 이미 입력받고 있습니다. 이걸 뒤집으면 학생 프로파일이 됩니다.
- 단, **축 간 상관을 먼저 확인**해야 합니다. 어려운 문항은 다섯 축이 같이 올라가서
  사실상 1축일 수 있습니다. 60문항쯤 쌓인 뒤 상관행렬을 찍고, 통과해야 켭니다.
