## 0. 이 문서를 어떻게 검수하는가

### 0-1. 30분 안에 끝내는 검수 순서

1. **§3의 표에서 '과정별 행 수'만 먼저 본다.** 한 과정이 6~10행이면 정상이다. 그보다 많거나 적으면 §4를 본다.
2. **§4의 「원장 확인 목록」 14개 항목에 O/X를 친다.** 이 14개가 이 문서에서 지어낼 수 없어 남겨 둔 전부다.
3. **§3의 단원 이름을 학원이 실제로 쓰는 교재 목차와 나란히 놓고 본다.** 이름이 다르면 행을 고치지 말고 **§5의 `aliases`에 학원 표기를 추가**한다. 이름을 고치면 다른 교재·기출과 어긋난다.
4. **`order`(진도 순서)를 강사 진도표와 대조한다.** 이 문서의 order는 **교육과정 배열 순서**이지 학원 진도 순서가 아니다. 2015 개정 고시는 스스로 "내용의 배열 순서가 교수·학습의 순서를 의미하지 않는다"고 적어 두었다.

### 0-2. 학원 실제 진도와 다를 가능성이 높은 지점 — 먼저 짚는다

| 지점 | 무엇이 흔들리나 | 어디서 확인 |
|---|---|---|
| **중등 학기 배치** | 2022·2015 개정 모두 중학교 성취기준을 **중1~3 '학년군'으로 일괄 제시**하고 학기를 나누지 않는다. `수학 2-1` / `수학 2-2` 경계는 **교과서 출판사 분권 관행**이다. ±1단원 흔들린다 | §4-A1 |
| **2022 개정 중3** | 교과서가 **아직 없다**(2027학년도부터 사용). 중3-1/3-2의 16행은 성취기준에서 역산한 것이다 | §4-A2 |
| **중1-2 통계 순서** | '자료의 정리와 해석' 다음에 '대푯값'을 두었으나, 대푯값을 먼저 하는 교과서가 있다 | §4-A4 |
| **2015 수학(상) 10행** | 다른 13개 고등 과정이 6~8행인데 여기만 10행이다. **묶지 말 것** — 묶으면 교재·기출과 단원명이 어긋난다 | §4-B1 |
| **공통수학1 9행 / 중1-2 9행** | 화면 상한 12행 안이므로 그대로 둔다 | §4-B1 |
| **`order` 전체** | 교육과정 배열 순서다. 특히 2015 수학(하)의 '경우의 수'를 학기 초에 먼저 빼는 교재가 있다 | §4-C1 |
| **2022 기하 대단원 순서** | 2022는 이차곡선 → 공간도형과 공간좌표 → 벡터인데, 2015 순서(이차곡선 → 평면벡터 → 공간도형)를 유지하는 출판사가 있을 수 있다 | §4-C2 |

### 0-3. 이 마스터만으로는 지표가 켜지지 않는다 — 반드시 같이 읽을 것

**이 문서를 시드해도 히트맵은 뜨지 않는다.** 채워 넣을 입력 경로가 저장소에 없기 때문이다.

- `classes` 문서에 **과정 필드가 없다**(`src/features/LectureManager.js:598` = name / lecturerId / subject / schedules / season / status). 중3반이 공통수학1을 나가도 남는 것은 `subject: '수학'`뿐이다.
- 개념테스트 과목 select도 **대과목 4개뿐**이다(`src/features/ExamDiagnosticInput.js:757-762`).
- 단원 입력칸은 **자유 텍스트**다(`ExamDiagnosticInput.js:771-772`), 저장 시 `trim()`만 한다.
- 게다가 `ExamDiagnosticInput.js:297`의 useMemo 의존성 배열에 `customTestMeta.unitName`이 **빠져 있어**, 지금 `responses[].unitRaw`가 `null`로 저장되고 있을 가능성이 높다.

→ 마스터는 **필요조건이지 충분조건이 아니다.** §7의 코드 수정이 같이 가야 산다.

## 1. 규격

### 1-1. 필드 정의

```
artifacts/{APP_ID}/public/data/curriculum_units/{unitId}

  unitId        string   "MATH_H1_S1-2022-050"     문서 키. §1-2 규칙
  curriculum    string   "2022" | "2015"           ← 학교급은 넣지 않는다
  schoolLevel   string   "중학교" | "고등학교"
  courseCode    string   "MATH_H1_S1"              ← 기존 STANDARD_CODES 재사용
  course        string   "공통수학1"                ← 앱 표기와 글자까지 동일. 조인 금지
  categoryOrder number   20                        ← 대단원 진도 순서 (10 단위)
  category      string   "방정식과 부등식"           ← 층1 = 교과서 대단원
  unitName      string   "이차방정식과 이차함수"      ← 층2 = 판정 단위
  order         number    50                       ← 과정 안 통합 순서 (10 단위)
  areaName      string   "방정식과 부등식"           ← 교육과정 영역명. 참고용
  ontologyArea  string   "ALG"                     ← 참고용. 조인 금지. 화면 비노출
  standards     string   "10공수1-02-04~06"        ← 성취기준 범위. 참고용
  aliases       string[] ["이차함수와 그래프", ...]   ← 백필·검색용. 필수
  nodeIds       string[] []                        ← 온톨로지 실연결 자리. 2단계에 채움
  note          string                             ← 강사용 범위 메모
  active        boolean  true
```

**제안안에서 바꾼 것 7가지와 이유**

| # | 변경 | 이유 |
|---|---|---|
| 1 | `unitId`에 **curriculum을 박았다** | `courseCode`가 두 교육과정에 공용이다. `MATH_H1_S1`은 2022에서 공통수학1이고 2015에서 수학(상)인데, **단원 집합이 다르다** — 2022에서 행렬이 신설되고 도형의 방정식이 공통수학2로 이동했다. curriculum 없이 조회하면 행이 섞이는 정도가 아니라 **다른 과목 단원이 돌아온다** |
| 2 | `courseCode`를 **신규 코드가 아니라 기존 `STANDARD_CODES` 재사용** | `subjectMapper.js:24-30`에 이미 7개가 있고, `:195-201`이 과목명→코드를, `:246-258`이 코드→과목명을 왕복 변환한다. `HS22-COMMON1` 같은 새 코드를 만들면 저장소에 **세 번째 과목 어휘**가 생긴다 |
| 3 | 중등 `courseCode`는 `MATH_MID_{학년}_{학기}` | 기존 `MATH_MID` 하나로는 6개 과정을 못 가른다. **새 어휘를 만들지 않고 기존 `MATH_MID`를 학년·학기로 확장**한 형태다. `course` 문자열 `수학 2-1`에서 `^수학 (\d)-(\d)$`로 기계 파생된다 |
| 4 | `ontologyArea`를 **조인 키에서 내리고 `nodeIds[]`를 신설** | 온톨로지 실측에서 `PAT` 137 · `SKL` 178 · `TRP` 52 = **367개 노드에 영역 코드가 없다**. 영역으로 조인하면 skill/pattern/trap이 통째로 빠진다. 게다가 영역은 5개뿐이라 단원 194개와 조인해도 정보량이 거의 0이다 |
| 5 | `categoryOrder` 신설 | 없으면 대단원이 가나다순으로 정렬되어 진도가 무너진다 |
| 6 | `aliases[]` 신설 | 백필의 전제조건이다. §1-4 참조 |
| 7 | `semester` · `grade` **미도입** | §1-5 참조 |

### 1-2. unitId 생성 규칙

```
unitId = `${courseCode}-${curriculum}-${String(order).padStart(3,'0')}`
```

예: `MATH_H1_S1-2022-050` · `MATH_H1_S1-2015-050` · `MATH_MID_2_1-2022-030`

- **3자리 zero-pad**: 문자열 사전순 정렬이 곧 진도 순서가 된다. `-50`과 `-100`을 섞으면 뒤집힌다.
- **curriculum이 키 한가운데 들어간다**: 위 표 #1의 이유. 이것이 없으면 2015 고3 문서와 2022 고1 문서가 **같은 ID로 충돌한다.**
- **학년을 키에 넣지 않는다**: 목동은 선행이 기본이라 중3반이 공통수학1을 나간다. 학년을 키에 박으면 같은 학생의 같은 단원 기록이 진급 때 갈라진다.
- `order`는 10 단위다. 나중에 단원을 쪼갤 때 사이에 넣을 자리를 남긴다(온톨로지 `display_order` 규약과 동일).

### 1-3. 조회 규칙 — 두 가지를 금지한다

```js
// ✅ 올바른 조회
where('courseCode','==',code).where('curriculum','==','2022').orderBy('order')

// ❌ 금지 1 — curriculum 없는 조회
where('courseCode','==','MATH_H1_S1')     // 2022 공통수학1 + 2015 수학(상)이 섞여 돌아온다

// ❌ 금지 2 — course 문자열 조인
where('course','==',someString)           // 표기 흔들림 하나에 조용히 0건이 된다
```

`(courseCode, curriculum)` 복합 인덱스를 **권고가 아니라 스키마 제약으로 못 박는다.**
`getStandardSubjectCode(schoolType, subjectName)`(`subjectMapper.js:172-201`)는 교육과정 구분을 **반환하지 않는다** — 이 함수만 믿고 조인하면 2015 고3 데이터와 2022 고1 데이터가 한 행에 합쳐진다. 화면이 `year`·`grade`를 함께 들고 있는지 먼저 확인해야 curriculum을 복원할 수 있다.

### 1-4. aliases는 선택이 아니다

기존 기록의 백필은 `responses[].unitRaw ??= 문서의 unitName`으로 **결측만 복구**된다. 그 `unitName` 자체가 자유 텍스트이므로 `삼각함수` / `삼각함수 ` / `삼각함수(1)` / `삼각함수 심화`가 그대로 들어온다. **백필은 정규화가 아니다.** aliases 사전이 없으면 마스터를 만들어도 히트맵에 4행이 그대로 남는다.

aliases에 넣어야 하는 것: ① 교재별 다른 표기 ② 교육과정 정본 표기(unitName을 교재 표기로 잡은 행) ③ 학원 진도표 표기 ④ 대단원명 변형. §5의 각 행에 1차분을 넣어 두었고, **학원 교재를 보고 원장이 채워야 완성된다.**

### 1-5. 학기 경계 — `semester`를 넣지 않는 이유

창(window)의 단위는 학기가 아니라 **`courseCode`**다. 히트맵 = 지금 나가는 course의 단원들이고, 두 course를 동시에 나가면 섹션이 2개다.

1. **비대칭은 이미 해소되어 있다.** 중등은 course 문자열(`수학 2-1`)에 학기가 박혀 있고, 고1은 `subjectMapper.js:24-25`가 이미 `MATH_H1_S1: '고1 1학기 (공통수학1, 수학 상)'`로 course=학기를 정의한다.
2. **고2·고3은 학교마다 배치가 다르다.** 대수를 1학기에 할지 2학기에 할지는 학교 재량이다. 마스터가 모르는 사실을 필드로 만들면 틀린 값이 박힌다. 학기 정보는 이미 있는 `academic_calendars`(`AcademicCalendarManager.js:35`)가 답한다.
3. **학원의 실제 시간 축은 학기가 아니라 시즌 6개다** — `SEASON_TYPES = ['윈터시즌','1학기 중간고사','1학기 기말고사','서머시즌','2학기 중간고사','2학기 기말고사']`(`AcademicCalendarManager.js:37`), `student_exam_diagnostics.season`에 이미 저장 중이다.

### 1-6. category / unitName이 각각 무엇인가 — 층 규칙을 못 박는다

이 규칙이 이 문서에서 가장 오해받기 쉬운 부분이다. **학교급마다 다른 축을 쓰지 않는다.**

> **`category` = 교과서·교재 목차의 대단원(로마숫자 묶음).**
> **`unitName` = 그 아래에서 성취기준 묶음 하나에 대응하는 판정 단위.**

이 단일 규칙이 세 곳에서 각각 다른 이름과 만난다:

| | category가 일치하는 것 | 값 예시 |
|---|---|---|
| 2022 고등 | 교육과정 **영역명**과 일치 | 다항식 / 방정식과 부등식 / 경우의 수 / 행렬 |
| 2015 고등 | 교육과정 **핵심 개념**과 일치(영역명은 더 굵다) | 다항식 / 도형의 방정식 / 집합과 명제 |
| 중등 | 교과서 대단원. 교육과정 **영역명보다 한 층 아래** | 소인수분해 / 정수와 유리수 / 문자와 식 |

교육과정 영역명은 별도 필드 **`areaName`**으로 뺐다(중등 = 수와 연산 / 변화와 관계 / 도형과 측정 / 자료와 가능성, 2015 고등 공통 = 문자와 식 / 기하 / 함수 / 수와 연산 / 확률과 통계).

**초안 3개가 이 지점에서 갈려 있었고, 검증이 지적한 대로 그대로 두면 히트맵 배지가 과정마다 다른 층을 가리킨다.** 중등에서 영역명(4개)을 category로 쓰면 한 과정에 배지 값이 2개뿐이라 정보량이 거의 없고, 2015 고등에서 영역명을 쓰면 수학(상) 10행이 배지 2개(문자와 식 / 기하)로 뭉친다. 그래서 **교과서 대단원**으로 통일했다.

### 1-7. 온톨로지와의 연결 — 왜 별개의 축인가

온톨로지는 **개념 구조**로 나눈다(해석학 > 미분 > 도함수의 활용). 단원 마스터는 **진도 순서**로 나눈다(공통수학1 > 방정식과 부등식 > 이차방정식과 이차함수). 한 개념이 여러 과정에서 다시 나오고(이차함수는 중3·공통수학1 둘 다), 한 단원이 여러 개념을 묶는다(공통수학1의 '복소수'는 온톨로지에서 수와 연산이고 같은 대단원의 나머지는 대수다). 두 축은 **다대다**이므로 어느 한쪽이 다른 쪽의 부분집합이 될 수 없고, 따라서 중복이 아니다.

연결은 **`nodeIds[]` 하나로만** 한다. 이유:

- **`course` 문자열 조인은 조용히 0건이 된다.** 온톨로지는 `미적분I` · `확률과통계`(공백 없음), 앱은 `미적분 I` · `확률과 통계`(공백 있음)다. 온톨로지 노드 **447/912개(49%)**가 여기에 걸린다. 게다가 온톨로지 course 축에는 **2015 개정 과목이 0개, 중등 6과목이 0개, 초등이 0개**다. 표기 문제가 아니라 데이터 부재다.
- **`ontologyArea` 조인은 30%를 빠뜨린다.** ID에 영역 코드가 없는 노드가 367개다(`PAT` 137 · `SKL` 178 · `TRP` 52). 이 필드는 **화면에 노출하지 않고 조인에도 쓰지 않는다.** §3의 '영역' 열은 검수용 참고값이다.
- **`nodeIds[]`는 지금 채우지 않는다.** 문항 마스터(`concept_test_items`)가 생긴 뒤(2단계), 강사가 **단원 단위로 1회**, 기존 기록 소급 없이 채운다. 194행 × 평균 8노드 ≈ 1,550개 연결이고 O(문항)이 아니라 **O(단원)**이라 한 번 만들면 끝난다.

> 참고: `docs/ontology/STATUS.md`의 '노드 1,159 / 간선 2,561'과 `MATH_INDICATORS.md:423`의 같은 수치는 **낡았다.** 2026-08-16 build.json 실측은 노드 1,221(concept 854 / skill 178 / pattern 137 / trap 52) · 간선 2,697이다.

## 2. 입도 결정과 근거

### 2-1. 결론

**판정 단위(`unitName`) = 성취기준 묶음 하나에 대응하는 층.** 고등에서는 교과서 중단원, 중등에서도 교과서 중단원이다. 과정당 **6~10행**.

"대단원이냐 중단원이냐"는 학교급마다 답이 갈리는 잘못된 질문이다. 정답은 **"한 course가 6~10행이 되는 층"**이고, 세 계산이 그 답으로 수렴한다.

### 2-2. 공급량 — 판정 창 안에 몇 단원을 판정할 수 있는가

| 값 | 근거 |
|---|---|
| 시즌 1개 ≈ 8주, 주 1회 개념테스트 10문항 → **시즌당 80문항** | ⚠ **저장소에서 확인되지 않은 가정**. §4-D1 |
| 만료 창 120일 ≈ 2시즌 → **160문항 = 16회** | `MATH_INDICATORS.md:168` |
| 무응답(`mark==='blank'`) 제외 → 회당 유효 시도 8~10 (평균 9) | 지표 공통 규칙 |
| 2단계 지표3('3주 뒤')이 delayed 30%를 가져감 → current 몫 회당 6~7 | `MATH_INDICATORS.md` 지표3 |
| 판정 게이트 = **단원당 시도 8문항** | `MATH_INDICATORS.md:168` |
| → **판정 1단원당 1.3~1.6회** | |
| → **창 안에 판정 가능한 단원 = 16 ÷ 1.6 ≈ 10개** | |

**이 문서의 최대 행 수가 정확히 10이다**(2015 수학(상)). 즉 어느 과정을 나가든 창 안에 전 단원이 판정된다.

층을 잘게 하면 무너진다. 소단원 층(과목당 45~65개)이면 8×50 = **400문항 = 40회 = 5시즌 = 20개월**이 걸려 만료 120일 안에 구조적으로 불가능하다. 판정률이 20%에 머문다.

### 2-3. '최근 2회차만' 규칙의 생사

`MATH_INDICATORS.md:160`은 같은 단원 재평가 시 **최근 2회차만** 쓴다. 중2-1(16회) 기준:

| 층 | 단원 수 | 단원당 회차 | 결과 |
|---|---|---|---|
| 대단원(영역) | 2 | 8.0 | 관측의 **75%(120문항)가 버려진다** |
| **이 문서(중단원)** | **7** | **2.3** | 2회차가 실재한다. 폐기율 13% |
| 소단원 | 20 | 0.8 | 2회차가 없다 → 규칙이 **정의상 무효** |

### 2-4. 처방 — 판정 단위 = 클리닉 배정 단위

`clinic_tasks` 문서 ID가 `${studentId}_${date}_${classId}`(`LectureManager.js:240`)이므로 **클리닉 1회 = 하루 1건**이다. 하루치 과제로 번역되는 굵기가 이 층이다.

- 너무 굵음: `변화와 관계 = 아직`(중2-1에서 식의 계산 + 부등식 + 연립방정식 + 일차함수 전부)은 하루치로 배정할 수 없다. `MATH_INDICATORS.md` §5-2의 summaryLine 고정 형식 *"지금 가장 먼저 볼 것은 ○○ 단원이고…"*도 문장이 성립하지 않는다.
- 너무 잚: `일차함수의 그래프의 평행이동`은 15분짜리라 배정 단위보다 작다.

### 2-5. 규모 — 소단원은 온톨로지의 중복이다

소단원 마스터는 약 900행이 되어 온톨로지 concept **854개**와 자릿수가 같아진다. 같은 알갱이를 두 축에 두 번 쓰는 것이고, 이 문서가 §1-7에서 세운 전제가 그 지점에서 무너진다. **194행은 온톨로지 노드 1,221개와 한 자리 차이**라 겹치지 않는다.

### 2-6. 화면이 읽을 수 있는 행 수

| 상한 | 값 | 근거 |
|---|---|---|
| 목표 | 6~10행 (= course 1개) | 현 렌더는 `AcademyUniverse.js:624`의 `p-6 rounded-3xl` 카드 2열 그리드. 압축형 행(단원명 + '12문제 중 9개' + 날짜)을 64px로 잡으면 학부모 모바일 가시 영역 560~640px에 8~9행이 스크롤 없이 들어간다 |
| 화면 상한 | 12행 | 두 course를 동시에 나가는 선행 학생도 `수학 3-2` 7행 + `공통수학1` 9행 = 16행이라 **상한을 넘는다** → §4-E2 |
| 데이터 상한 | 10행 | §2-2 |

`MATH_INDICATORS.md` §5-2가 요구하는 카드 4요소(개수 / 라벨 / 세줄 메타 / 학원 조치)를 모든 행에 펼치면 행당 220~260px가 되어 2~3행밖에 안 된다. **4요소는 탭한 행 하나만 펼치는 구조여야 한다.**

### 2-7. 자료가 얇을 때 — 롤업 판정 (저장 계층을 늘리지 않는다)

`unitName`에서 시도 8문항 미달이면 같은 `category`로 풀링해 재판정한다. `unitName` 판정이 하나라도 서면 롤업을 해제한다.
표기: `[대단원] 이차방정식과 이차함수 — 묶어서 봄 (14문제 중 9개)`
롤업 판정에도 Wilson 구간과 '최근 2회차만'을 그대로 적용한다. 이것으로 3계층 없이 굵기를 동적으로 만든다.

| **G5** | 지표1 선행수정 2번 | "`unitRaw ??= doc.unitName`으로 **100% 복구된다**"는 과한 표현이다. **복구되는 것은 자유 텍스트이고, 결측 복구이지 정규화가 아니다.** 마스터 매칭에는 별도의 사람 검수 공수가 필요하고 그 공수가 문서에 잡혀 있지 않다 |

| **G7** | 지표1 · 지표3 | **두 지표가 같은 문항을 놓고 경쟁한다는 계산이 문서에 없다.** 지표3이 10문항 중 3문항을 delayed로 가져가면 current 몫이 7이 되어 8문항 게이트를 한 회로 못 넘는다. **판정 용량이 절반이 된다.** 2단계 착수 시 1단계 히트맵의 판정 속도가 눈에 띄게 느려질 것을 지금 예고해 두지 않으면, §9-1이 경고한 '게이트를 낮추자'는 압력이 정확히 그 시점에 온다 |

## 5. 시드 데이터

### 5-0. 시드 스크립트 (요지)

아래 JSON은 과정 단위로 묶여 있다. 공통 필드(`course` · `courseCode` · `curriculum` · `schoolLevel`)를 각 unit에 복제하고 `unitId`를 생성해서 쓴다. **문서 하나만 읽고도 판정이 되도록 반드시 복제한다.**

```js
// tools/seed-curriculum-units.js
import { doc, setDoc, writeBatch } from 'firebase/firestore';
const PATH = `artifacts/${APP_ID}/public/data/curriculum_units`;
const pad = n => String(n).padStart(3, '0');

for (const c of ALL_COURSES) {          // §5-1 ~ §5-4 배열을 이어붙인 것
  for (const u of c.units) {
    const unitId = `${c.courseCode}-${c.curriculum}-${pad(u.order)}`;
    await setDoc(doc(db, PATH, unitId), {
      unitId,
      curriculum : c.curriculum,
      schoolLevel: c.schoolLevel,
      courseCode : c.courseCode,
      course     : c.course,            // 표시용. 조인 금지
      categoryOrder: u.co,
      category   : u.cat,
      unitName   : u.name,
      order      : u.order,
      areaName   : u.area,
      ontologyArea: u.oa,               // 참고용. 조인 금지. 화면 비노출
      standards  : u.std || '',
      aliases    : u.al  || [],
      nodeIds    : [],                  // 2단계에 강사가 단원 단위로 채움
      note       : u.note || '',
      active     : true
    }, { merge: true });
  }
}
```

**시드 후 즉시 확인할 3줄**
```js
// 1) 총 194건인가
// 2) unitId 중복 0건인가  (curriculum 누락 시 여기서 터진다)
// 3) course별 행 수가 6~10인가
```

> ⚠ `std` 값의 `Ⅰ`(U+2160)·`Ⅱ`(U+2161)는 고시 표기다. **이 글자를 `course` 필드에 복사하지 말 것** — 앱은 ASCII `I`(U+0049)를 쓴다.

## 6. 선행 학습 처리

### 6-1. 원칙 두 줄

1. **`courseCode`·`curriculum`은 학생의 학년이나 반 이름에서 추론하지 않는다.** 마스터 드롭다운에서 강사가 고른 `unitId`를 그대로 따라온다. 선행이 기본인 학원에서 학년 추론은 **정확히 틀린다.**
2. **판정의 경계는 학년이 아니라 `(courseCode, curriculum)`이다.** 같은 과정을 계속 보고 있으면 학년이 바뀌어도 이월한다.

### 6-2. 중3반이 공통수학1을 나갈 때 — 실제 기록

```
artifacts/{APP_ID}/public/data/student_exam_diagnostics/{docId}

  schemaVersion : 2
  testCategory  : 'concept'
  subject       : '수학'                    ← 기존 대과목. 바꾸지 않는다(집계·화면 키)
  schoolType    : '중학교'                  ← 학생 학적. 진도가 아니다
  grade         : 3                         ← 학생 학적. 판정에 쓰지 않는다
  classId       : 'cls_xxx'
  className     : '중3A'                    ← 남되 판정에 쓰지 않는다
  season        : '서머시즌'

  ▼ 신규 3개 — 전부 마스터 드롭다운에서 따라온다
  courseCode    : 'MATH_H1_S1'              ← '중3'에서 추론 금지
  curriculum    : '2022'                    ← courseCode 단독으로는 단원 집합이 안 정해진다
  unitId        : 'MATH_H1_S1-2022-050'

  unitName      : '이차방정식과 이차함수'     ← 마스터 값 스냅샷
  unitRaw       : '이차함수 최대최소'         ← 강사가 친 원문. 절대 지우지 않는다

  responses: [
    { displayNumber:1, mark:'correct', points:10,
      unitId :'MATH_H1_S1-2022-050',
      unitRaw:'이차함수 최대최소' },
    ...
  ]
```

**`unitRaw`를 남기는 이유**: `ExamDiagnosticInput.js:283-284`의 주석이 이미 같은 이유를 적어 두었다 — *"시험 마스터를 나중에 고치면 과거 채점 기록이 어느 단원이었는지 되살릴 방법이 없습니다."* 마스터를 고쳐도 과거 채점의 사실은 남아야 한다.

**학생 학년을 여기 박지 않는 이유**: `users` 문서에 이미 있고, 여기 박으면 진급 때 같은 학생의 기록이 갈라진다.

### 6-3. 이 학생의 히트맵은 무엇을 보여주나

```
[수학 3-2]                      ← 학교 진도 (MATH_MID_3_2 / 2022)
  삼각비              익힘        9문제 중 8개 · 6월 12일
  삼각비의 활용        익히는 중   10문제 중 7개 · 6월 26일
  ...                              (7행)

[공통수학1]                     ← 학원 선행 (MATH_H1_S1 / 2022)
  다항식의 연산        익힘        8문제 중 8개 · 7월 3일
  이차방정식과 이차함수 자료 모으는 중  4문제 중 3개
  ...                              (9행)
```

**총 16행으로 §2-6의 12행 상한을 넘는다.** 두 course 섹션 중 하나는 접혀 있어야 한다(§4-E2). 이것이 이 문서가 해결하지 못한 유일한 화면 문제다.

### 6-4. 진급했을 때 — 이월 규칙

이 학생이 2027년 3월 고1이 되면:

| | 이월하나 | 이유 |
|---|---|---|
| `수학 3-2` 7행 | **이월 후 만료 대기** | 과정이 끝났다. `(MATH_MID_3_2, 2022)` 관측은 그대로 남고 만료 규칙에 따라 자연히 감춰진다 |
| `공통수학1` 9행 | **그대로 이월** | 학년은 바뀌었지만 `(MATH_H1_S1, 2022)`는 같다. 리셋하면 중3에 뗀 단원의 관측이 통째로 사라진다 |

`MATH_INDICATORS.md` §8-3의 *"학년이 바뀌면 대비 지표를 이월하지 않는다"*는 이 학원에서 역효과다(§4-G6).

### 6-5. 재수생

`curriculum: '2015'` + 기존 `courseCode`로 표현된다. 다만 **온톨로지 course 축에 2015 개정 과목이 0개**이므로 온톨로지 조인은 성립하지 않는다. `nodeIds[]`를 강사가 직접 채우기 전까지 재수생은 온톨로지 연결 밖이다.

### 6-6. 마스터에 없는 단원 — 폴백을 반드시 둔다

선행 학원이므로 **마스터가 항상 뒤처진다.** 저장을 막으면 조교가 비슷한 걸 아무거나 고르고, 그것은 자유 텍스트보다 나쁘다(자유 텍스트는 표기 흔들림이지만 잘못된 마스터 참조는 **틀린 판정**이고 발견하기 훨씬 어렵다).

> **규칙**: 드롭다운에 `— 목록에 없음 —` 옵션을 두고, 선택 시 `unitId: null` + `unitRaw` 자유 입력을 받는다. **그 건수를 원장 화면에 노출한다.** 이 숫자가 마스터를 언제 갱신해야 하는지 알려주는 유일한 신호다.
