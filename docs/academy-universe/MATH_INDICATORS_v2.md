# 수학 능력 지표 체계 v2 — 확정본

> v1(`MATH_INDICATORS.md`)의 **지표 목록은 폐기**한다. 이 문서가 정본이다.
> v1에서 살아남는 것은 §8에 명시했다. 측정 원칙·위험 완화·배관 요구사항은 대부분 그대로 유효하다.
>
> 원장 확정: 4축 다이아몬드 · 심화 추론력은 해금 스탯 · 실행 지구력은 학습 역량에만 · 과제 신뢰도는 숙제 정답률을 기다린다.

---

## 0. 무엇이 바뀌었나

v1은 **측정하기 쉬운 대비**에서 축을 뽑았다(긴 계산 vs 짧은 계산). v2는 **학생이 실제로 문제를 푸는 순서**에서 뽑는다.

| | v1 | v2 |
|---|---|---|
| 축을 뽑은 기준 | 측정 가능한 조건 대비 | 풀이 파이프라인의 단계 |
| 이름 | 긴 계산 / 바뀐 문제 / 많은 조건 | 조건 독해력 / 개념 조립력 / 유형 매칭력 / 연산 견고함 |
| 오답 원인 분류 | 지표와 별개 체계 | **지표와 1:1** |
| 계층 | 평면 7개 | 인지 역량 / 학습 역량 2계층 |
| 도형 | 레이더 폐기 | 다이아몬드 4축 (척도가 통일되므로 성립) |

**핵심 이득**: 파이프라인이면 오답 원인이 **가장 이른 실패 지점 하나**로 특정된다. v1이 따로 만든 오답 분류(손도 못 댐 / 계산에서 무너짐 / 조건 빠뜨림 / 옮겨 적기)가 축과 그대로 붙는다. 두 체계를 따로 유지할 필요가 없다.

## 1. 구조

```
[인지 역량]  문제 풀이 과정에 직접 개입하는 능력
  다이아몬드 4축
      조건 독해력 · 개념 조립력 · 유형 매칭력 · 연산 견고함
  해금 스탯
      심화 추론력   ← 4축이 일정 수준에 도달해야 열린다

[학습 역량]  성적을 장기적으로 유지하고 끌어올리는 엔진
  지식 보존율   단원별 히트맵
  과제 신뢰도   괴리 표시
  실행 지구력   체력바 (칸 = 개수)
```

**두 계층을 시각적으로 섞지 않는다.** 검토 과정에서 실행 지구력을 다이아몬드에 넣거나 링으로 감싸는 안이 나왔으나 폐기했다 — 인지 축과 행동량은 눈금이 다르고, 한 도형에 넣으면 면적이 거짓말을 한다.

> 인지 4축 30 · 실행 100 학생과, 인지 4축 60 · 실행 50 학생의 면적이 비슷해진다.
> 앞은 "열심히 하는데 안 되는" 학생이고 뒤는 "될 만한" 학생인데 도형이 같아 보인다.

파이프라인이 실제로 4단계이므로 **다이아몬드가 자연스러운 형태**다. 오각형을 만들려고 다섯 번째를 끼워 넣지 않는다.

## 2. 인지 역량 — 풀이 파이프라인 4단계

```
조건 독해 → 개념 조립 → 유형 매칭 → 연산
                   ↘ (파이프라인이 안 통하는 문항) → 심화 추론
```

**판정 규칙: 가장 이른 실패 지점 하나만 센다.** "시간에 쫓겨 조건을 놓친 계산 실수"는 조건 독해 실패다. 이 규칙 하나로 축이 상호배타가 되고, 오답 하나가 여러 축을 동시에 깎는 일이 없어진다.

### 공통 규칙

- **대상**: `schemaVersion === 2` 이고 `maxScore > 0` 인 기록만. 그 이전은 만점 100 고정 시절이라 점수 자체가 틀리다.
- **무응답 제외**: `mark === 'blank'` 문항은 모든 분모에서 뺀다.
- **반 평균 차감**: 보고값 = (이 학생의 값) − (같은 시험을 본 반의 평균). 문항이 유난히 어려웠던 효과를 소거한다. 반 유효 인원 8명 미만이면 판정에 쓰지 않고 누적만 한다.
- **표시 3줄 필수**: 어떻게 쟀는가 / 몇 문제로 쟀는가 / 마지막 본 날.
- **라벨보다 개수가 먼저**: 표본이 게이트 미만이면 라벨을 내지 않고 `11문제 중 5개`처럼 관측만 보여준다. 화면은 첫날부터 차고, 틀린 라벨은 한 번도 나가지 않는다.

### 2-1. 조건 독해력 (Condition Decoding)

**학부모에게** 문제에 적힌 조건을 빠짐없이 찾아내고, 그 말이 무슨 뜻인지 알아보는 능력입니다.

**학생의 말** *"아, 이 조건을 못 봤어요"* / *"이 말이 판별식 쓰라는 말인지 몰랐어요"*

**데이터 출처**
- 주 신호: `concept_test_items.condMany === true` 문항의 정답률 vs 일반 문항 정답률의 간격
- 보조 신호: `clinic_tasks.items[].errorTag === '조건을 빠뜨림'` 빈도

**측정**
```
간격 = (일반 문항 정답률) − (조건 많은 문항 정답률)
보고값 = 간격 − 반 평균 간격
```
간격이 클수록 조건 독해에서 무너진다. 화면에는 간격이 아니라 두 값을 나란히 쓴다.
`조건 적은 문항 22개 중 19개 / 조건 많은 문항 11개 중 4개`

**최소 표본** 조건 많은 문항 8개, 일반 문항 8개
**수집 비용** 출제 시 강사 체크박스 1개(`condMany`). 문항당 1초. 재사용 시 0.

**이 축이 낮으면 틀리는 문항** 조건이 3개 이상 붙은 서술형. 같은 유형인데 표현만 바뀐 문항. 그림·표에서 조건을 읽어야 하는 문항.

### 2-2. 개념 조립력 (Concept Assembly)

**학부모에게** 배운 개념을 정확히 알고, 문제에 필요한 개념을 꺼내어 풀이의 뼈대를 세우는 능력입니다.

**학생의 말** *"공식을 까먹었어요"* / *"어떤 공식을 써야 할지 감을 못 잡았어요"*

**데이터 출처** `student_exam_diagnostics`(testCategory='concept') · `responses[].mark` · `responses[].unitId`
**신규 태그 없음.** 단원 태그만 있으면 켜진다. 그래서 이 축이 1단계다.

**측정**
```
최근 범위(current) 문항 중 해당 개념을 처음 적용하는 문항의 정답률
보고값 = 정답률 − 반 평균 정답률
```

**최소 표본** 시도 8문항
**수집 비용** 자동

**이 축이 낮으면 틀리는 문항** 배운 직후인데 못 푸는 기본 문항. 개념 하나만 알면 되는 단일 개념 문항.

> v1의 '단원 진행'은 이 축으로 흡수됐다. 단원별 분해는 §3-1 히트맵이 담당한다.
> 같은 데이터에서 **축은 종합을, 히트맵은 분해를** 보여준다.

### 2-3. 유형 매칭력 (Pattern Matching)

**학부모에게** 훈련한 문제 유형을 기억하고, 같은 방식으로 다시 풀어내는 능력입니다.

**학생의 말** *"풀어본 문젠데 어떻게 시작하는지 까먹었어요"*

**데이터 출처** `responses[].nodeIds[]`(개념 노드) + 시간에 따른 정답 이력

**측정**
```
분모: 같은 개념 노드로 이전에 정답 이력이 있는 문항 (최근 범위 안)
분자: 그중 지금 틀린 문항
보고값 = (1 − 재실패율) − 반 평균
```

**유형 목록을 만들지 않는다.** 기본형 문항은 개념 자체가 유형이므로, "같은 개념을 전에 맞혔는데 지금 틀렸다"가 곧 유형 매칭 실패다. 온톨로지의 pattern 정책(`docs/ontology/STATUS.md:55` — 기본형은 pattern 으로 신설하지 않는다)과 충돌하지 않는다.

**대신 필요한 것: 개념 단위 태그.** 단원 태그로는 오판이 난다 — '이차함수' 단원에서 판별식을 맞히고 최대최소를 틀리면 "같은 개념 실패"로 잘못 센다. 온톨로지 concept 노드를 문항에 붙이는 것이 이 축의 인프라이며, 이는 어차피 온톨로지 연결을 위해 해야 하는 작업이다.

**지식 보존율과의 경계 — 약속으로 정한다**

| | 대상 창 |
|---|---|
| 유형 매칭력 | **최근 범위** 안에서의 같은 개념 재실패 |
| 지식 보존율 | **3주 이상 지난 범위**에서의 정답률 |

자연의 경계가 아니라 약속이다. 정하지 않으면 두 축이 같은 관측을 다르게 이름 붙여 두 번 보여준다.

**최소 표본** 재출현 개념 8개
**수집 비용** 출제 시 강사가 개념 노드 선택. 문항당 3~5초. 재사용 시 0.

### 2-4. 연산 견고함 (Calculation Stability)

**학부모에게** 세운 식을 끝까지 정확하게 계산해 내는 능력입니다.

**학생의 말** *"다 풀었는데 마지막에 +를 −로 잘못 적었어요"*

**데이터 출처** `concept_test_items.calcHeavy` + `clinic_tasks.items[].errorTag`

**측정**
```
간격 = (계산 가벼운 문항 정답률) − (계산 무거운 문항 정답률)
보고값 = 간격 − 반 평균 간격
```
화면 표기는 두 값 병기.

**최소 표본** 계산 무거운 문항 8개, 가벼운 문항 8개
**수집 비용** 출제 시 강사 체크박스 1개(`calcHeavy`). 문항당 1초.

**이 축이 낮으면 틀리는 문항** 식은 맞게 세웠는데 답이 틀린 문항. 전개·약분이 긴 문항.

### 2-5. 심화 추론력 (Advanced Reasoning) — 해금 스탯

**학부모에게** 처음 보는 문제에서, 아는 개념을 비틀어 새로운 풀이 길을 뚫어내는 능력입니다.

**학생의 말** *"해설지 보면 아는데, 저 혼자서는 절대 이렇게 생각 못 할 것 같아요"*

**왜 축이 아니라 해금인가 — 선택 효과**

이 능력이 관측되려면 학생이 앞 네 단계를 통과해 거기까지 도달해야 한다. 앞에서 막힌 학생은 관측이 **0이 아니라 아예 없다**. 축으로 두면 강한 학생만 값이 차고, 약한 학생은 늘 찌그러진 한 변으로 보인다. 그것은 능력 차이가 아니라 측정 구조의 그림자다.

해금으로 두면 같은 사실이 **결핍이 아니라 목표**가 된다.

**해금 조건**
```
인지 4축 중 3개 이상이 판정되고, 그 3개가 반 평균 이상
  AND
고난도 문항(novelForm) 시도 관측 12개 이상
```

**해금 전 표시**
```
🔒 심화 추론력
   조건 독해력과 연산 견고함을 먼저 채우면 열립니다. (2/3)
```

**해금 후 측정** 고난도(`novelForm`) 문항에서의 정답률. 반 평균 차감.

**최소 표본** 12문항 (다른 축보다 높게 잡는다 — 희소하고 변동이 크다)
**수집 비용** 출제 시 강사 체크박스 1개(`novelForm`)

## 3. 학습 역량

### 3-1. 지식 보존율 (Knowledge Retention)

**학부모에게** 수업에서 배운 것이 시간이 지나도 얼마나 남아 있는지를 단원별로 보여드립니다.

**학생의 말** *"한 달 전에 할 때는 다 맞았는데, 지금 다시 푸니까 다 까먹었어요"*

**v1에서 바뀐 것**: 숙제 흡수량을 **뺐다**. 숙제를 많이 했는데 못 익힌 것과, 익혔는데 시간이 지나 잊은 것은 처방이 정반대인데 합치면 같은 값이 된다. 게다가 숙제 흡수량은 측정할 신호가 없어 이름만 약속하게 된다. 그 실체는 §3-2 과제 신뢰도가 담당한다.

**데이터 출처** `concept_test_items.recallSpan`(`current` | `delayed`) + `responses[].unitId`

**측정 (단원별)**
```
보존율 = (delayed 문항 정답률) / (current 시점 정답률)
```

**표시 — 단원별 히트맵. 한 칸에 두 값을 담는다.**
```
단원                  배울 때     3주 뒤
이차방정식             18/20       7/11      ← 보존 낮음
이차함수               15/18      13/15      ← 유지됨
삼각비                 12/14      (미측정)   ← delayed 관측 없음
```

**초기에는 대부분 '배울 때' 값만 찬다.** delayed 관측이 쌓이려면 최소 3주가 지나야 하므로 구조적으로 그렇다. 결함이 아니라 정상이며, 그 사이 히트맵은 **단원 도달도**로 기능한다.

**최소 표본** 단원별 current 8문항 / delayed 8문항
**수집 비용** 출제 시 강사 2택(`recallSpan`). 문항당 1초.
**단, 문항 마스터가 있어야 성립한다** — 조교는 채점 화면에서 그 문항이 3주 전 범위인지 알 방법이 없다.

### 3-2. 과제 신뢰도 (Assignment Reliability)

**학부모에게** 숙제에서 맞힌 만큼 시험에서도 맞히는지를 봅니다. 벌어져 있으면 공부하는 방식을 바꿔야 한다는 신호입니다.

**측정**
```
괴리 = (숙제 정답률) − (테스트 정답률)
보고값 = 괴리 − 반 평균 괴리
```

**반 평균 차감이 필수다.** 숙제는 시간 제한이 없고 참고서를 볼 수 있으므로 **모든 학생에게 괴리가 존재한다.** 절대 괴리는 의미가 없고 또래 대비만 의미가 있다.

**표시** 두 값을 나란히. 괴리가 반 평균보다 크게 벌어졌을 때만 강조.
```
숙제 34/36 (94%)  ·  테스트 11/25 (44%)  ·  반 평균보다 28%p 더 벌어짐
```

**처방**
- 괴리가 크다 → 답지를 보거나 손만 움직이고 있다. **숙제 방식을 바꿔야 한다.**
- 괴리가 작은데 둘 다 낮다 → 숙제는 정직한데 양이나 난이도가 안 맞는다.

**데이터 출처 — 지금 없다**
```js
// LectureManager.js:249 — clinic_tasks.items[]
{ taskContent, isCompleted, incompleteDetails }   // 완료 여부만. 정답률 없음
```
**신규 입력 필요**: 숙제 정답 개수 / 전체 개수.
원장 결정에 따라 **완료 여부로 대체하지 않고 정답률을 기다린다.**

**수집 비용** 조교가 숙제 채점 후 숫자 2개 입력. 학생당 과제당 약 10초. 클리닉에서 이미 숙제를 함께 보고 있으므로 판단이 아니라 계수다.

**최소 표본** 과제·테스트 짝 4쌍

---

### 3-3. 실행 지구력 (Execution Stamina)

**학부모에게** 계획된 학습량을 흔들림 없이 해내고 있는지를 보여드립니다.

**측정 — 비율이 아니라 개수**
```
배정된 과제 12건 중 완료 9건
출석 예정 20회 중 출석 18회
```

**비율을 쓰지 않는 이유.** `실행 지구력 30%`는 학부모에게 곧바로 **"우리 애가 게으르다"**로 읽힌다. `12회 중 9회`는 사실로 읽힌다. 일곱 요소 중 낙인 위험이 가장 큰 자리이므로 눈금을 사실로 고정한다.

**표시** 체력바. 다만 **칸의 개수가 곧 과제 수**다. 12칸 중 9칸이 찬 모양이면 보이는 것은 체력바이고 읽히는 것은 개수다.

**메타인지 장치 — 반 평균 대비 개수**
```
이번 시즌 우리 반 평균 제출 10건 · 너 7건
```
순위(하위 20%)가 아니라 평균 대비 개수를 쓴다. 비교의 교육 효과는 유지하고 서열 낙인은 피한다.

**데이터 출처** `clinic_tasks.items[].isCompleted`(있음) · `attendance_logs`(있으나 분모 문제)

**주의 — 출석은 1단계에서 쓰지 않는다.** `attendance_logs`는 '무기록'과 '결석'이 구분되지 않아, **아무도 신경 쓰지 않은 학생일수록 출석률이 100%로 나온다.** 분모를 `classes.schedules`에서 생성한 뒤에 켠다.

**최소 표본** 배정 과제 6건

## 4. 오답 원인 분류 = 파이프라인 단계

v1은 지표와 오답 분류를 별개로 만들었다. v2에서는 **하나다.**

### 계층 1 — 전수, 조교, 관찰 사실만
```
responses[].mark : 'correct' | 'partial' | 'wrong' | 'blank'
```
`blank`(무응답)는 답안지에 눈으로 보이는 사실이다. **판단이 아니라 대조다.**

### 계층 2 — 표본, 클리닉에서, 고정 칩

| 칩 | 대응 축 | 처방 |
|---|---|---|
| **조건을 빠뜨림** | 조건 독해력 | 조건 밑줄·체크리스트 |
| **손도 못 댐** | 개념 조립력 | 개념 재확인 |
| **풀어본 건데 시작을 못 함** | 유형 매칭력 | 유형 재노출 |
| **방향은 맞고 계산에서 무너짐** | 연산 견고함 | 계산 훈련, 중간식 쓰기 |
| **다 풀고 옮겨 적기에서 틀림** | 연산 견고함 | 검산 습관 |

**상호배타 규칙: 가장 이른 실패 지점을 고른다.**

**왜 클리닉에만 두는가.** 조교가 전수 판정하려면 오답마다 풀이를 다시 읽어야 한다. 그것은 원장이 이미 폐기한 `lucky` 판정과 같은 비용 구조다. 반면 클리닉에서는 이미 학생 풀이를 함께 보고 있고, 이미 태그를 자유 텍스트로 타이핑하고 있다(`ClinicDashboard.js:1596`). 자유 텍스트를 고정 칩으로 바꾸면 **조교 시간 증가 0**이면서 집계 가능한 신호가 생긴다.

**`responses[].errorType` 5분류 전수 입력은 하지 않는다.** 읽는 코드가 저장소 전체에 0곳이고, 채워도 화면에 아무 변화가 없다. 필드 자체는 남긴다.

## 5. 문항 태깅 규격

```
concept_test_items/{itemId}
  itemId
  unitId       : "MATH_H1_S1-2022-050"   ← curriculum_units 참조
  points       : 5
  nodeIds      : []          ← 온톨로지 개념 노드. 유형 매칭력의 재료
  recallSpan   : 'current' | 'delayed' | null
  calcHeavy    : true | false | null
  condMany     : true | false | null
  novelForm    : true | false | null
  createdBy, createdAt, reusedCount

concept_test_forms/{formId}
  title, classIds[], date, itemIds[]
```

**null을 반드시 허용한다.** 이진 플래그의 기본값은 false 가 아니라 **null**이다. 미태깅과 '아니오'를 구별하지 못하면 축이 조용히 왜곡된다. 계산 계층은 null 문항을 양쪽 군에서 모두 제외하고, 시험별 **태그 채움률**을 기록한다. 채움률 90% 미만 시험은 해당 축 산출에서 통째로 제외한다.

**비용 구조 — 이 설계의 핵심 경제학**
```
조교 방식:  O(학생 × 오답)     15명 × 오답 8개 = 120회 판단
강사 방식:  O(문항)            10문항 등록 1분, 5개 반에 쳐도 1회
```
조교에게 늘어나는 것은 **무응답(빈칸) 표시** 하나뿐이다. 채점 화면의 오답 버튼을 (정답 → 오답 → 무응답 → 정답) 순환으로 바꾼다. 추가 판단 0, 학생당 약 4초.

**할당량을 두지 않는다.** "매 시험에 계산 무거운 문항 3개를 넣어라"는 순간 평가가 대시보드를 먹이려고 왜곡된다. 규칙은 **있는 그대로 태그한다**이고, 축이 안 켜지면 그것이 정답이다.

## 6. 화면 설계

### 6-1. 첫날부터 채운다 — 라벨이 아니라 관측으로

원장 결정: 빈 화면을 두지 않는다. 다만 **채우는 재료는 라벨이 아니라 실측 개수**다.

| 표본 | 표시 |
|---|---|
| 3문항 | `3문제 중 3개` — 라벨 없음 |
| 20문항 | `20문제 중 18개` + 축 값 |

표본 크기가 숫자 안에 그대로 보이므로 별도 주의 문구가 거의 필요 없다. `3문제 중 3개`를 보면 사람이 알아서 감을 잡는다.

**초기 안내 문구**(학원 말투로 다듬어야 함)
> 데이터를 모으는 초기에는 문제 수가 적어 값이 흔들릴 수 있습니다.
> 지금 보이는 숫자는 **실제로 푼 문제의 개수**입니다.

### 6-2. 대상별 노출

| | 다이아몬드 4축 | 심화 추론력 | 히트맵 | 과제 신뢰도 | 실행 지구력 |
|---|---|---|---|---|---|
| 학생 | ○ | ○ (해금 진행 포함) | ○ | ○ | ○ (반 평균 대비) |
| 학부모 | ○ | **해금 후만** | ○ | ○ | ○ (개수만) |
| 강사 | ○ | ○ | ○ + 문항 단위 | ○ | ○ |
| 데스크 | 요약만 | ✕ | ✕ | ✕ | ○ |

**학부모에게 해금 전 자물쇠를 보이지 않는다.** 학생에게는 목표로 읽히지만 학부모에게는 결핍으로 읽힌다.

### 6-3. 낮은 값 옆에는 학원의 조치가 있어야 한다

낮은 숫자를 본 학부모의 첫 질문은 "그럼 학원은 뭘 했나"이고, 답이 '타고난 차이'가 되면 그 상담은 이탈로 끝난다. 조치는 **클리닉 배정 기록에서 자동 생성**하고 강사가 덮어쓴다. 사람의 성실성에 걸린 게이트는 곧 침묵 스위치가 된다.

## 9. 남은 결정과 미검증 가정

### 원장 결정 대기
1. **A1** 중등 학기 배치 — 교육과정이 중1~3을 학년군으로 묶어 학기를 나누지 않는다. `수학 2-1`/`2-2` 경계는 교재 분권 관행이라 학원 진도표와 ±1단원 어긋날 수 있다
2. **D1** 개념테스트를 시즌당 몇 회 보는가 — 주 1회 가정 시 판정 가능 단원 10개, 시즌 4회면 5개. **이 숫자 하나에 마스터의 절반이 걸려 있다**
3. 초기 안내 문구의 학원 말투
4. 숙제 정답률 입력을 조교 업무에 넣는 것의 수용 가능성

### 확신하지 못하는 것
- 네 이진 플래그(`condMany` / `calcHeavy` / `novelForm` / `recallSpan`)가 서로 분리되는지 **아직 아무도 데이터로 확인하지 않았다.** 분리되지 않으면 3·4단계 축이 동시에 죽고 남는 것은 개념 조립력과 지식 보존율 둘뿐이다. 그 시나리오를 받아들일 수 있어야 시작할 수 있다
- 3단계 착지 시점(약 15주)은 태그 공급량에 대한 산술 투사이지 측정치가 아니다
- 조교 인원과 주당 처리량은 저장소에서 확인할 수 없다

### 정직한 평가

**측정 정밀도로는 대형 플랫폼을 이길 수 없다.** 회차당 수십 명 규모에서는 IRT도 BKT도 모수가 서지 않는다.

**이길 수 있는 축은 둘이다.**

1. **설명 가능성** — "조건 적은 문항 22개 중 19개 / 조건 많은 문항 11개 중 4개. 개념은 아는데 조건을 놓칩니다. 그래서 조건 밑줄 훈련을 넣었습니다." 대형 업체의 "취약 개념: 이차함수 68점"이 못 하는 말이다.
2. **실행까지 이어지는 것** — 진단 → 클리닉 배정 → 과제 체크 → 다음 시험이 한 학생 안에서 이어진 데이터.

**다만 지금 그 해자는 파여 있지 않다.** 개념테스트 문항은 채점할 때마다 즉석 생성되고 사라진다. 문항이 없으니 개념 태그도, 온톨로지 연결도, 재사용도 없다. **지표보다 먼저 만들어야 하는 것은 문항이다.**

**실패한다면 가장 유력한 원인**은 초기 몇 달간 대부분의 축이 얇은 표본으로 보일 때 게이트를 낮추는 것이다. 게이트를 낮추면 노이즈를 능력으로 파는 것이 되고, 이번에는 난수가 아니라 실제 데이터에서 나온 숫자라 **훨씬 그럴듯하고 훨씬 발견하기 어렵다.**
