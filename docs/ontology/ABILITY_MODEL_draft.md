# 학생 수학 능력치 수치화 — 설계 초안 (2026-08-19)

> 목표(원장, 2026-08-19): **문제집의 문제별로 학생의 오답 이유를 밝혀서 학생의 수학적
> 능력치를 수치화한다.** 이 문서는 온톨로지 세션이 앱 세션(HANDOFF.md·mathProfile)의
> 맥락을 읽고 작성한 통합 설계 초안이다. 원장 승인 전 — 구현 착수 금지.

## 1. 진단: 두 세션의 작업이 이미 한 점으로 수렴하고 있다

| 이미 있는 것 | 어디에 | 무엇을 주는가 |
|---|---|---|
| 문제별 정오 데이터 | 앱: 숙제 채점 `wrongNumbers[]`/`blankNumbers[]` (교재·단원 매핑), 시험 진단 `responses[]`+`errorType`, 클리닉 오답 원인 고정 칩 | **(학생, 교재, 문항번호, 정오)** 원자 기록이 이미 쌓이는 중 |
| 문항 난이도 축 | 앱: 내신연구소 IDI 5축 (상관 검증 대기) | 문항 쪽 특성 |
| 오답 "이유"의 사전 | 온톨로지: **trap 116개** (전국 상습 오류를 오답 메커니즘 단위로 명세) + concept 1,321 + skill 175 + pattern 136 | 오답 이유의 통제 어휘 — 자유 텍스트가 아니라 ID |
| 단원별 집계 엔진 | 앱: `mathProfile.js` (Wilson 구간, 라벨 게이트, 숙제·시험 분리) | 집계 철학과 코드 기반 |

**빠진 것은 딱 하나 — 문항-노드 태깅층이다.**
`(교재ID, 문항번호) → 필요 노드들 + 예상 오답 시나리오(trap)` 매핑이 생기는 순간,
조교가 클릭한 틀린 번호 하나하나가 "단원 정답률"이 아니라 **"어느 노드가 무너졌는가"**의
증거가 된다. 단원(현재 granularity) → 노드(1,321개 granularity)로 해상도가 뛴다.

## 2. 태깅층 스키마 (저작권 청정 — 문제 본문을 저장하지 않는다)

온톨로지 데이터 레포 `tags/textbook/` 에 교재별 파일:

```yaml
# tags/textbook/마플시너지_대수_2022.yaml
- no: "Ⅲ-03-STEP01-1024"        # 소단원-스텝-문항번호
  nodes: [ANA-05-02-02, SKL-0092]  # 이 문항을 풀려면 필요한 노드 (주 1 + 보조)
  traps:                            # 예상 오답 시나리오
    - trap: TRP-0096
      wrong_value: "-45"            # 이 함정에 빠지면 나오는 오답값 (객관식이면 선지 번호)
      # → 학생 오답값과 자동 매칭되면 오답 이유가 사람 개입 없이 확정된다
  difficulty: 2                     # 교재 자체 위계 (STEP01/02/03)
```

- 문항번호·태그·예상오답값만 저장 — **본문 없음, 출판사 저작권과 무관**
- 예상 오답값은 trap 노드의 함정 시나리오를 그 문항의 수치에 적용해 AI가 미리 계산

## 3. 오답 이유를 밝히는 세 경로 (자동 → 반자동 → 수동)

1. **오답값 자동 매칭** — 학생이 적어낸 답 = 태깅층의 `wrong_value` → trap 확정. 개입 0
   (전제: 숙제 채점 입력에 "틀린 번호"만이 아니라 선택적으로 "학생이 쓴 답"을 받는 확장)
2. **조교 클리닉 칩** — 이미 있는 고정 칩을 trap/노드 ID와 1:1로 연결 (칩 어휘 확장)
3. **AI 재풀이 진단** — 오답값이 어떤 trap 과도 안 맞으면, AI가 그 문항을 해당 trap 들로
   일부러 틀리게 풀어 학생 오답을 재현하는 시나리오를 탐색 (배치, 사후)

`errorType` 원칙 준수: 시간 부족(`blank`·미응시)은 오답 이유 진단에 넣지 않는다.

## 4. 능력치 모델 — 단계적으로, 기존 철학 그대로

**1단계 (즉시 가능): 노드별 Wilson 라벨** — mathProfile 의 검증된 방식을 단원→노드로 내리기만.
노드별 (맞은 증거, 시도 증거) 카운트 → 익힘/익히는 중/아직. 숙제·시험 트랙 분리 유지.
- 귀속 규칙: 정답 → 태깅된 모든 노드에 +1. 오답 + trap 확정 → **trap 이 지목한 노드에만** -1.
  오답 + 이유 미확정 → 태깅 노드들에 분수 귀속(1/n) — "판정 못 하면 거르지 않는다" 원칙
- **지어내지 않는다**: 증거 없는 노드는 빈칸이 아니라 "기록 없음 + 무엇을 풀면 채워지는지"

**2단계 (데이터 쌓인 후): 선수 그래프 전파** — prerequisite 간선으로 "이 노드가 아직이면
후속 노드들 위험" 표시(표시용, 판정 아님). 온톨로지의 간선이 여기서 처음 실전 투입된다.

**3단계 (원장 결정 사항): 종합 수치** — 노드 숙련도 벡터 → 단원/과목 상위 집계,
IDI 5축 학생 프로파일과 결합. 축 상관 검증(60문항+) 통과가 선행 조건.

## 5. 왜 이 순서인가 (평가)

- 능력치의 신뢰도는 모델이 아니라 **증거의 해상도**에서 나온다. BKT/IRT 같은 모델을 먼저
  들이는 것보다, 클릭 한 번이 노드 증거가 되게 만드는 태깅층이 전체 가치의 8할이다
- 조교 입력 부담이 **늘지 않는다** — 지금 하는 틀린 번호 클릭 그대로. 해상도는 태깅층이 올린다
- 아카데미 유니버스 사고(데이터 없이 숫자 지어내기)의 교훈과 정합: 잰 것만 낸다

## 6. 파일럿 제안 (조교 검수 대기 중에 진행 가능)

**마플시너지 대수 Ⅲ단원(수열) STEP01 전 문항 태깅** — 이유: 온톨로지가 가장 두꺼운 영역
(개념+skill/pattern/trap 완비), 재원생 고2 수요 최다.

- 원장 제공 필요: **해당 페이지 사진** (문항번호와 문제를 식별할 수 있게. 본문은 태깅
  판단에만 쓰고 저장하지 않음 — 기출PDF 와 같은 방식)
- AI 작업: 문항별 노드 태깅 + trap 별 예상 오답값 계산 + 자기검증 → 조교 검수 페이지
- 앱 작업(옆 세션과 분업): 숙제 채점에 "학생 답 입력(선택)" 확장 + 노드별 집계를
  mathProfile 에 추가 + 학생별 노드 리포트 화면

## 7. 결정 필요 (원장)
