# 임페리얼 수학 온톨로지 — 스키마 v2

> 이 문서가 기준입니다. `scripts/validate-ontology.js` 가 여기 적힌 규칙을 기계적으로 검사합니다.
> 문서와 검사기가 어긋나면 **문서를 고치고 검사기를 맞춥니다** (반대가 아닙니다).

---

## 0. 왜 v2 인가

v1(현재 571개)은 **개념만** 담을 수 있었습니다. `relations` 에는 `prerequisite` 하나뿐이고,
모든 노드가 `level: 세분류` 로 같았습니다.

그런데 수능·내신 고득점에 실제로 필요한 것은 개념이 아니라 그 위에 얹히는 층입니다.

- **스킬** — "√(a²−x²) 가 보이면 x = a·sinθ 로 치환한다"
- **유형** — "구간이 나뉜 함수의 미분가능성을 묻는 문제"
- **함정** — "절댓값을 벗길 때 부호를 나누지 않는다"

이들은 *개념이 아닙니다*. 개념 하나에 붙지도 않습니다(여러 개념을 가로지릅니다).
v1 구조에 억지로 넣으면 "개념인 척하는 스킬" 이 되어 나중에 전부 다시 써야 합니다.

**지금이 가장 싼 시점입니다.** `practical_concepts` / `action_guidelines` / `misconceptions`
세 섹션은 571개 전부 플레이스홀더라 **옮길 내용이 0** 입니다. 한 달 뒤에는 수백 개를 다시 써야 합니다.

## 1. 노드 종류 (`type`)

| type | 무엇 | 예 |
|---|---|---|
| `concept` | 교과 개념. 정의와 성질. | 미분계수의 정의 |
| `skill` | 실행 절차. 언제 쓰는지가 핵심. | 삼각치환 |
| `pattern` | 문제 유형. 알아보는 법이 핵심. | 구간 나뉜 함수의 미분가능성 |
| `trap` | 오개념·함정. 학생이 어떻게 틀리는지가 핵심. | 절댓값 부호 분리 누락 |

### 무엇이 어느 타입인가 — 판정 기준

한 줄 설명만으로는 갈리지 않습니다. **"이 노드를 지우면 학생이 무엇을 못 하게 되는가"** 로 판정합니다.

| 지웠을 때 | 타입 |
|---|---|
| 정의·정리를 진술하지 못한다 | `concept` |
| 문제를 보고 무엇을 할지 몰라 멈춘다 | `skill` |
| 문제의 겉모습을 알아보지 못한다 | `pattern` |
| 자신 있게 틀린다 | `trap` |

**한 파일 안에 여러 타입의 내용이 섞여 있으면 반드시 쪼갭니다.**
예: `ALG-03-02-03` 은 "판별식 D=b²−4ac 의 정의"(concept) 와
"문제에 「중근을 갖는다」가 보이면 D=0 을 세운다"(skill) 가 한 파일에 들어 있습니다.

### ⚠️ 기존 571개는 "전부 concept" 이 아닙니다

초안에는 그렇게 적었으나 **사실이 아닙니다.** 이 문서가 skill 의 예로 든 '삼각치환'은
이미 `ANA-08-03-05` 라는 concept 파일로 존재하고, pattern 의 예로 든
'구간 나뉜 함수의 미분가능성'도 `ANA-07-01-07` 로 존재합니다.
기계적으로 전부 `concept` 을 찍으면 **같은 내용의 쌍둥이 노드가 100개 이상 생깁니다.**

→ 이관은 "전부 concept" 이 아니라 **재분류**입니다. 10장 참조.

## 2. 공통 필드 (모든 노드)

**필수는 최소로 둡니다.** 지키지 못할 필수 항목은 플레이스홀더를 낳습니다 —
v1 에서 `trigger_signals` 가 571개 전부 "작성 예정" 으로 남은 것이 그 증거입니다.

```yaml
# ── 필수 (없으면 ❌ 빌드 중단) ────────────────────────────
id: ANA-07-03-05            # 3장 참조
type: concept               # concept | skill | pattern | trap
title: "함수의 극값과 미분계수"
major_category: "해석학"
middle_category: "미분"
sub_category: "도함수의 활용"
status: draft               # 5장 참조
source: ai                  # ai | human | ai+human
updated_at: 2026-08-09

# ── 선택 ────────────────────────────────────────────────
grade: 고2                  # 초3~초6 | 중1~중3 | 고1~고3 | 무관
course: 미적분I              # 아래 표. 해당 없으면 생략
tier: 기본                   # 기본 | 심화 | 킬러
display_order: 30           # 4장 참조. 10 단위 권장
verified_by: []             # 5장 참조
keywords:
  - 극값
relations:                  # 6장 참조. 없는 관계는 생략
  prerequisite:
    - ANA-07-02-01
```

> `grade` 는 선택이지만 **13번 검증 규칙(선수관계 방향)** 이 이 값을 씁니다.
> 비어 있으면 그 노드는 방향 검사에서 빠집니다. 폴더 위치로 자동 추정해 채우십시오.

### `course` 값 (2022 개정)

`공통수학1` `공통수학2` `대수` `미적분I` `미적분II` `확률과통계` `기하`
초·중등은 생략하고 `grade` 만 씁니다.

## 3. ID 규칙

```
<영역><중분류>-<소분류>-<세분류>       예: ANA-07-03-05
```

영역 코드: `NUM` 수와연산 · `ALG` 대수 · `ANA` 해석학 · `GEO` 기하 · `PRB` 확률과통계

**`skill` / `pattern` / `trap` 은 접두사 + 일련번호를 씁니다. 좌표를 쓰지 않습니다.**

```
SKL-0001     스킬        _skills/SKL-0001.yaml
PAT-0001     유형        _patterns/PAT-0001.yaml
TRP-0001     함정        _traps/TRP-0001.yaml
```

초안에서는 `SKL-ANA-07-03-01` 처럼 개념 좌표를 빌려 쓰게 했으나 **이건 곧바로 깨집니다.**
한 개념에 스킬이 둘이면 ID 가 글자 하나까지 같아집니다. 실제로 `ANA-08-03-05`(삼각치환법)
안에는 사인치환과 탄젠트치환 **두 개의 서로 다른 절차**가 이미 들어 있습니다.

일련번호를 쓰면 따라오는 이점이 큽니다.

- 개념 폴더에 접두어 번호가 충돌하지 않습니다 (현재 79개 폴더 전부 충돌 0, 빈 번호 0)
- 스킬이 여러 개념을 가로지르는 성질과 맞습니다. 소속은 `applies_to` 로만 표현합니다
- 개념을 재배치해도 스킬 ID 는 영향을 받지 않습니다

→ 그래서 **6번 검증 규칙(위치 일치)은 `concept` 에만 적용합니다.**

### ⚠️ ID 는 위치를 인코딩하지만, 위치가 바뀌어도 ID 는 바꾸지 않습니다

현재 571개는 ID 숫자와 폴더 번호가 100% 일치합니다. 그래서 중간에 중분류를 끼워 넣으면
뒤 폴더 번호가 밀리고 **ID 수백 개와 그것을 가리키는 선수관계가 전부 깨집니다.**

**해법: 폴더 번호를 바꾸지 않습니다.** 새 중분류는 뒤에 붙이고(`07_`, `08_`),
화면에 보이는 순서는 `display_order` 로 제어합니다.

정말 재배치가 필요하면 `scripts/restructure.js` 를 씁니다. 이 도구가
① 폴더 이동 ② 파일 내 id 갱신 ③ **모든 참조 갱신** ④ 검증 을 한 번에 처리합니다.
손으로 하지 마십시오.

## 4. `display_order`

숫자가 작을수록 먼저 배웁니다. **10 단위**로 매겨 중간 삽입 여지를 남깁니다.

```
10, 20, 30, ...        → 나중에 25 를 끼워 넣을 수 있음
```

같은 값이 있으면 `id` 순으로 정렬합니다.

## 5. `status` 와 검수 이력

작성자가 혼자이므로, **기계가 거를 수 있는 것은 기계가 거릅니다.**

| status | 뜻 | 다음 단계 |
|---|---|---|
| `draft` | AI 초안. 아직 아무 검증 없음 | 기계 검증 |
| `machine_verified` | 스키마·참조·수식·중복 통과 | 실행 검증 |
| `sampled` | 표본 검수에서 사람이 확인 | — |
| `human_confirmed` | 사람이 개별 확인 | — |

```yaml
verified_by:
  - { by: schema,             at: 2026-08-09, result: pass }
  - { by: counterexample,     at: 2026-08-09, result: pass, note: "기출 5문항 중 5개 일치" }
  - { by: human, who: 원장,    at: 2026-08-10, result: pass }
```

나중에 오류가 발견되면 **어느 단계에서 놓쳤는지** 추적되고, 그 단계를 고칠 수 있습니다.

## 6. 관계 (`relations`)

| 관계 | 방향 | 뜻 |
|---|---|---|
| `prerequisite` | 이 노드 ← 목록 | 목록을 먼저 알아야 이 노드를 배울 수 있다 |
| `applies_to` | 이 노드 → 목록 | 이 스킬/함정이 적용되는 개념들 |
| `combines` | 이 노드 → 목록 | 이 스킬은 목록의 스킬들이 결합된 것 |
| `alternative_to` | 상호 | 같은 문제를 푸는 다른 방법 |
| `faster_than` | 이 노드 → 목록 | 이 방법이 목록보다 계산이 빠르다 |
| `trap_of` | 이 노드 → 목록 | 이 함정은 목록의 개념/유형에서 자주 발생 |

```yaml
relations:
  prerequisite: [ANA-08-01-02]
  applies_to:   [ANA-08-02-01, ANA-08-02-03]
  faster_than:  [SKL-ANA-08-02-07]
  alternative_to: [SKL-ANA-08-02-09]
```

`faster_than` 이 중요합니다. **수능 고득점은 "풀 수 있나" 가 아니라 "제한 시간에 푸나" 입니다.**
v1 구조로는 이걸 표현할 방법이 아예 없었습니다.

**규칙**
- `prerequisite` 는 **직전 선수만** 적습니다. 조상의 조상은 적지 않습니다(중복 간선 금지).
- 모든 참조는 실재하는 id 여야 합니다.
- `prerequisite` 에 순환이 있으면 안 됩니다.

## 7. 타입별 몸체

각 타입은 **자기 몸체만** 가집니다. 다른 타입의 몸체가 있으면 검증 실패입니다.
(예: `trap` 노드에 `procedure` 가 있으면 오류)

### 7.1 `concept`

```yaml
definition:
  - id: ANA-07-03-05-D1
    title: "극값의 정의"
    content: "..."          # LaTeX 는 $...$

properties:                  # 선택
  - id: ANA-07-03-05-R1
    title: "극값과 미분계수의 관계"
    content: "..."

representative_examples:     # 선택
  - "f(x)=x³−3x 의 극댓값과 극솟값"
```

> v1 의 `core_concepts` 는 `definition` 으로 이름만 바뀝니다. 내용은 그대로입니다.

### 7.2 `skill`

```yaml
trigger_signals:             # 필수. 언제 꺼내 쓰는가
  - "적분 안에 √(a²−x²) 꼴이 보일 때"
  - "√ 안이 이차식이고 완전제곱으로 정리될 때"

procedure:                   # 필수. 단계별
  - "x = a·sinθ 로 치환한다 (−π/2 ≤ θ ≤ π/2)"
  - "dx = a·cosθ dθ 를 대입한다"
  - "적분 구간을 θ 기준으로 바꾼다"

why_it_works: "..."          # 필수. 근거. 암기 방지
limits:                      # 필수. 안 되는 경우
  - "√ 안이 x²−a² 꼴이면 sin 이 아니라 sec 치환"
```

### 7.3 `pattern`

> **판정 기준 (2026-08-13 원장 결정): 기본 개념·스킬만으로 충분히 알아보고 풀 수 있는
> 유형은 pattern 이 아니다.** pattern 은 "겉모습을 알아보는 것" 자체가 별도의 학습
> 대상일 때만 만든다 — 즉 개념을 다 알아도 유형 인식·해법 선택이 비자명한 준킬러
> 이상. 2~3점 기본형(공식 직결·단일 개념 적용)은 concept/skill 이 담당하며 pattern 을
> 신설하지 않는다. (근거: 커버리지 1라운드 실측 — 92문항 중 pattern 부재 82건의
> 대부분이 기본형이었고, 이를 전부 만들면 노드 수만 늘고 인식 가치가 없다)

```yaml
recognition:                 # 필수. 이 유형을 알아보는 법
  - "구간별로 다른 식이 주어지고 '미분가능' 조건이 붙는다"

required_skills:             # 필수. skill id 목록
  - SKL-ANA-07-01-03

typical_traps:               # 선택. trap id 목록
  - TRP-ANA-07-01-01

time_budget: 90              # 선택. 목표 풀이 시간(초)
```

### 7.4 `trap`

```yaml
symptom: "..."               # 필수. 학생이 어떻게 틀리는가
why: "..."                   # 필수. 왜 그렇게 생각하는가
diagnosis_message: "..."     # 필수. AI 튜터가 학생에게 할 말
correction: "..."            # 필수. 바로잡는 법
```

## 8. 문제 증거는 노드에 넣지 않습니다 ⭐

**`evidence` 필드는 없습니다.** 노드 안에 기출 목록을 넣으면 두 가지로 터집니다.

1. **개념 노드는 태그 대상이 아닙니다.** "자연수의 사칙연산"은 거의 모든 문제에 들어갑니다.
   기록해도 정보량이 0 이고 파일만 커집니다.
2. **목록이 무한히 자랍니다.** 20년치 + 문제집이면 노드 하나가 수백 줄이 되어
   사람이 검수할 수 없게 됩니다.

### 대신 분리합니다

```
온톨로지 YAML          지식 구조. 안정적. 사람이 검수.
      ↕ 참조만
tags/problems.jsonl    관측 데이터. 계속 쌓임. 기계가 처리.
      ↓ 빌드가 집계
build.json 의 stats    "이 스킬 47회 출제, 평균 정답률 31%"
```

```jsonl
{"problem":"2024수능-22","nodes":["SKL-ANA-08-02-01","PAT-ANA-07-01-01"],"correct_rate":0.03}
{"problem":"2023-09모평-30","nodes":["SKL-ANA-08-02-01"]}
```

### 태깅 규칙 — 결정적인 것만

> **문제에는 "그 문제를 푸는 데 결정적이었던 노드"만 답니다.**
> **전제로 깔린 기초 개념은 달지 않습니다. 선수관계를 거슬러 올라가면 자동으로 나옵니다.**

자연수·사칙연산이 모든 문제에 들어간다는 사실은, 그 노드가 거의 모든 노드의 **조상**이라는
형태로 이미 온톨로지에 표현되어 있습니다. 다시 적을 필요가 없습니다.

덕분에 문제당 태그가 2~4개로 유지되어 **AI 가 태깅해도 사람이 검수할 수 있습니다.**

### 초안에서 바뀐 것과 그 이유

**11번을 경고에서 중단으로 올렸습니다.** 자유 문구 마커는 금지하고,
각 몸체 항목에 `state: draft | filled` 를 명시하게 합니다. 빌드는 문자열을 추측하지 않고
이 플래그만 셉니다. 문구 검색으로는 막을 수 없다는 것이 v1 에서 이미 증명됐습니다 —
같은 마커가 `[2~3단계에서 작성 예정]` 과 `[2\~3단계에서 작성 예정]` 두 표기로 존재하고,
**한 문자열 안에 마커와 실제 원고가 공존**합니다(`…기록 예정. (예고: 실제 내용)` 176건).
경고로 두면 3,996건이 쌓이고 아무도 보지 않습니다.

**13번을 신설했습니다.** 지금 실제로 오류가 들어와 있는데 12개 규칙이 전부 통과시킵니다 —
`ALG-03-01-05` "연립일차방정식의 활용"(중2)이 `ALG-03-04-04` "이차함수의 최대와 최소"(고1)를
선수로 요구합니다. 방향이 거꾸로면 스킬트리의 목적 자체가 무너집니다.
보조 규칙으로 "같은 영역 안에서는 선수의 번호가 더 작아야 한다"도 넣습니다 —
같은 영역 간선 1,248개 중 위반이 5건뿐이라 소음이 거의 없습니다.

**14번을 신설했습니다.** `ALG-02-06-03` 이 `ALG-02-06-01` 의 통째 복제본입니다.
제목상 있어야 할 "부분분수" 개념이 실제로는 없는데 12개 규칙이 전부 통과시킵니다.

**15번을 신설했습니다.** `scripts/build-ontology.js:75-78` 은 파싱 실패를 `catch` 로 삼키고
`exit 0` 으로 끝납니다. 노드가 조용히 사라져도 CI 는 초록입니다.
지금 파싱 실패가 0건이므로 **이 규칙을 켤 수 있는 시점은 지금뿐입니다.**

### ⚠️ CI 가 지금은 PR 에서 돌지 않습니다

`build.yml` 이 push 트리거뿐이라 "❌ 는 머지를 막는다"가 **구조적으로 불가능**합니다.
검증기를 만들기 전에 `pull_request` 트리거를 먼저 추가해야 합니다.

## 10. v1 → v2 이관

### ⚠️ 초안의 이관표는 폐기합니다

초안은 "빈 3개 섹션 삭제 — 전부 플레이스홀더라 손실 없음" 이라고 적었습니다.
**571개를 전수 실측한 결과 사실이 아닙니다.**

| 필드 | 고유 원고 | 복붙 껍데기 | 원고 글자수 |
|---|---:|---:|---:|
| `action_guidelines.action` | 571 | 0 | 94,602 |
| `misconceptions.title` | 571 | 0 | 57,192 |
| `practical_concepts.title` | 471 | 100 | 49,401 |
| `action_guidelines.title` | 472 | 99 | 46,762 |
| `action_guidelines.situation` | 571 | 0 | 29,737 |
| `misconceptions.diagnosis_message` | 91 | 480 | 16,380 |
| `practical_concepts.content` | 89 | 482 | 15,913 |
| `misconceptions.symptom` | **1** | **570** | 26 |
| **합계** | **2,837** | **1,731** | **310,013** |

("같은 문장이 5회 이상 반복되면 껍데기" 기준. 예: `misconceptions.symptom` 은
571개 중 570개가 "학생들이 자주 빠지는 오류 현상 기록 예정" 한 문장입니다.)

즉 **삭제 대상 1,731건과 보존 대상 2,837건이 같은 섹션 안에 섞여 있습니다.**
섹션 단위로 지우면 31만 자가 사라지고, 그게 바로 목표인 "일타강사 층" 입니다.

> `ALG-02-04-05` — "두 다항식을 x−2로 나눈 나머지가 같을 때"
> 식을 세우지 않고 **P(2)=G(2) 로 미정계수를 1초 만에 구하는 스킬**

### 수확물이 v2 노드의 초안이 됩니다

백지에서 550개를 창작시키지 않습니다. AI 에게 **"교정"** 을 시킵니다.

창작보다 교정이 훨씬 검수하기 쉽습니다.
