# 임페리얼 수학 온톨로지 — 스키마 v2

> 이 문서가 기준입니다. `scripts/validate-ontology.js` 가 여기 적힌 규칙을 기계적으로 검사합니다.
> 문서와 검사기가 어긋나면 **문서를 고치고 검사기를 맞춥니다** (반대가 아닙니다).

---

## 0. 왜 v2 인가

v1(현재 571개)은 **개념만** 담을 수 있었습니다. `relations` 에는 `prerequisite` 하나뿐이고,
모든 노드가 `level: 세분류` 로 같았습니다.

그런데 수능·내신 고득점에 실제로 필요한 것은 개념이 아니라 그 위에 얹히는 층입니다.

- **스킬** — "√(a²−x²) 가 보이면 x = a·sinθ 로 치환한다"
- **유형** — "구간이 나뉜 함수의 미분가능성을 묻는 문제"
- **함정** — "절댓값을 벗길 때 부호를 나누지 않는다"

이들은 *개념이 아닙니다*. 개념 하나에 붙지도 않습니다(여러 개념을 가로지릅니다).
v1 구조에 억지로 넣으면 "개념인 척하는 스킬" 이 되어 나중에 전부 다시 써야 합니다.

**지금이 가장 싼 시점입니다.** `practical_concepts` / `action_guidelines` / `misconceptions`
세 섹션은 571개 전부 플레이스홀더라 **옮길 내용이 0** 입니다. 한 달 뒤에는 수백 개를 다시 써야 합니다.

## 1. 노드 종류 (`type`)

| type | 무엇 | 예 |
|---|---|---|
| `concept` | 교과 개념. 정의와 성질. | 미분계수의 정의 |
| `skill` | 실행 절차. 언제 쓰는지가 핵심. | 삼각치환 |
| `pattern` | 문제 유형. 알아보는 법이 핵심. | 구간 나뉜 함수의 미분가능성 |
| `trap` | 오개념·함정. 학생이 어떻게 틀리는지가 핵심. | 절댓값 부호 분리 누락 |

**기존 571개는 전부 `concept` 입니다.**

## 2. 공통 필드 (모든 노드)

```yaml
id: ANA-07-03-05            # 3장 참조
type: concept               # concept | skill | pattern | trap
title: "함수의 극값과 미분계수"

major_category: "해석학"
middle_category: "미분"
sub_category: "도함수의 활용"

grade: 고2                  # 초3~초6 | 중1~중3 | 고1~고3 | 무관
course: 미적분I              # 2장 아래 표. 해당 없으면 생략
tier: 기본                   # 기본 | 심화 | 킬러
display_order: 30           # 4장 참조. 10 단위 권장

status: draft               # 5장 참조
source: ai                  # ai | human | ai+human
verified_by: []             # 5장 참조
updated_at: 2026-08-09

keywords:
  - 극값
  - 미분계수

relations:                  # 6장 참조. 없는 관계는 생략
  prerequisite:
    - ANA-07-02-01
```

### `course` 값 (2022 개정)

`공통수학1` `공통수학2` `대수` `미적분I` `미적분II` `확률과통계` `기하`
초·중등은 생략하고 `grade` 만 씁니다.

## 3. ID 규칙

```
<영역><중분류>-<소분류>-<세분류>       예: ANA-07-03-05
```

영역 코드: `NUM` 수와연산 · `ALG` 대수 · `ANA` 해석학 · `GEO` 기하 · `PRB` 확률과통계

**`skill` / `pattern` / `trap` 은 접두사를 하나 더 붙입니다.**

```
SKL-ANA-07-03-01     스킬
PAT-ANA-07-03-01     유형
TRP-ANA-07-03-01     함정
```

> 뒤의 좌표는 "가장 관련 깊은 개념의 위치" 이며 소속을 뜻하지 않습니다.
> 스킬은 여러 개념을 가로지르므로, 실제 연결은 `applies_to` 관계로 표현합니다.

### ⚠️ ID 는 위치를 인코딩하지만, 위치가 바뀌어도 ID 는 바꾸지 않습니다

현재 571개는 ID 숫자와 폴더 번호가 100% 일치합니다. 그래서 중간에 중분류를 끼워 넣으면
뒤 폴더 번호가 밀리고 **ID 수백 개와 그것을 가리키는 선수관계가 전부 깨집니다.**

**해법: 폴더 번호를 바꾸지 않습니다.** 새 중분류는 뒤에 붙이고(`07_`, `08_`),
화면에 보이는 순서는 `display_order` 로 제어합니다.

정말 재배치가 필요하면 `scripts/restructure.js` 를 씁니다. 이 도구가
① 폴더 이동 ② 파일 내 id 갱신 ③ **모든 참조 갱신** ④ 검증 을 한 번에 처리합니다.
손으로 하지 마십시오.

---

## 4. `display_order`

숫자가 작을수록 먼저 배웁니다. **10 단위**로 매겨 중간 삽입 여지를 남깁니다.

```
10, 20, 30, ...        → 나중에 25 를 끼워 넣을 수 있음
```

같은 값이 있으면 `id` 순으로 정렬합니다.

---

## 5. `status` 와 검수 이력

작성자가 혼자이므로, **기계가 거를 수 있는 것은 기계가 거릅니다.**

| status | 뜻 | 다음 단계 |
|---|---|---|
| `draft` | AI 초안. 아직 아무 검증 없음 | 기계 검증 |
| `machine_verified` | 스키마·참조·수식·중복 통과 | 실행 검증 |
| `sampled` | 표본 검수에서 사람이 확인 | — |
| `human_confirmed` | 사람이 개별 확인 | — |

```yaml
verified_by:
  - { by: schema,             at: 2026-08-09, result: pass }
  - { by: counterexample,     at: 2026-08-09, result: pass, note: "기출 5문항 중 5개 일치" }
  - { by: human, who: 원장,    at: 2026-08-10, result: pass }
```

나중에 오류가 발견되면 **어느 단계에서 놓쳤는지** 추적되고, 그 단계를 고칠 수 있습니다.

## 6. 관계 (`relations`)

| 관계 | 방향 | 뜻 |
|---|---|---|
| `prerequisite` | 이 노드 ← 목록 | 목록을 먼저 알아야 이 노드를 배울 수 있다 |
| `applies_to` | 이 노드 → 목록 | 이 스킬/함정이 적용되는 개념들 |
| `combines` | 이 노드 → 목록 | 이 스킬은 목록의 스킬들이 결합된 것 |
| `alternative_to` | 상호 | 같은 문제를 푸는 다른 방법 |
| `faster_than` | 이 노드 → 목록 | 이 방법이 목록보다 계산이 빠르다 |
| `trap_of` | 이 노드 → 목록 | 이 함정은 목록의 개념/유형에서 자주 발생 |

```yaml
relations:
  prerequisite: [ANA-08-01-02]
  applies_to:   [ANA-08-02-01, ANA-08-02-03]
  faster_than:  [SKL-ANA-08-02-07]
  alternative_to: [SKL-ANA-08-02-09]
```

`faster_than` 이 중요합니다. **수능 고득점은 "풀 수 있나" 가 아니라 "제한 시간에 푸나" 입니다.**
v1 구조로는 이걸 표현할 방법이 아예 없었습니다.

**규칙**
- `prerequisite` 는 **직전 선수만** 적습니다. 조상의 조상은 적지 않습니다(중복 간선 금지).
- 모든 참조는 실재하는 id 여야 합니다.
- `prerequisite` 에 순환이 있으면 안 됩니다.

## 7. 타입별 몸체

각 타입은 **자기 몸체만** 가집니다. 다른 타입의 몸체가 있으면 검증 실패입니다.
(예: `trap` 노드에 `procedure` 가 있으면 오류)

### 7.1 `concept`

```yaml
definition:
  - id: ANA-07-03-05-D1
    title: "극값의 정의"
    content: "..."          # LaTeX 는 $...$

properties:                  # 선택
  - id: ANA-07-03-05-R1
    title: "극값과 미분계수의 관계"
    content: "..."

representative_examples:     # 선택
  - "f(x)=x³−3x 의 극댓값과 극솟값"
```

> v1 의 `core_concepts` 는 `definition` 으로 이름만 바뀝니다. 내용은 그대로입니다.

### 7.2 `skill`

```yaml
trigger_signals:             # 필수. 언제 꺼내 쓰는가
  - "적분 안에 √(a²−x²) 꼴이 보일 때"
  - "√ 안이 이차식이고 완전제곱으로 정리될 때"

procedure:                   # 필수. 단계별
  - "x = a·sinθ 로 치환한다 (−π/2 ≤ θ ≤ π/2)"
  - "dx = a·cosθ dθ 를 대입한다"
  - "적분 구간을 θ 기준으로 바꾼다"

why_it_works: "..."          # 필수. 근거. 암기 방지
limits:                      # 필수. 안 되는 경우
  - "√ 안이 x²−a² 꼴이면 sin 이 아니라 sec 치환"
```

### 7.3 `pattern`

```yaml
recognition:                 # 필수. 이 유형을 알아보는 법
  - "구간별로 다른 식이 주어지고 '미분가능' 조건이 붙는다"

required_skills:             # 필수. skill id 목록
  - SKL-ANA-07-01-03

typical_traps:               # 선택. trap id 목록
  - TRP-ANA-07-01-01

time_budget: 90              # 선택. 목표 풀이 시간(초)
```

### 7.4 `trap`

```yaml
symptom: "..."               # 필수. 학생이 어떻게 틀리는가
why: "..."                   # 필수. 왜 그렇게 생각하는가
diagnosis_message: "..."     # 필수. AI 튜터가 학생에게 할 말
correction: "..."            # 필수. 바로잡는 법
```

## 8. 문제 증거는 노드에 넣지 않습니다 ⭐

**`evidence` 필드는 없습니다.** 노드 안에 기출 목록을 넣으면 두 가지로 터집니다.

1. **개념 노드는 태그 대상이 아닙니다.** "자연수의 사칙연산"은 거의 모든 문제에 들어갑니다.
   기록해도 정보량이 0 이고 파일만 커집니다.
2. **목록이 무한히 자랍니다.** 20년치 + 문제집이면 노드 하나가 수백 줄이 되어
   사람이 검수할 수 없게 됩니다.

### 대신 분리합니다

```
온톨로지 YAML          지식 구조. 안정적. 사람이 검수.
      ↕ 참조만
tags/problems.jsonl    관측 데이터. 계속 쌓임. 기계가 처리.
      ↓ 빌드가 집계
build.json 의 stats    "이 스킬 47회 출제, 평균 정답률 31%"
```

```jsonl
{"problem":"2024수능-22","nodes":["SKL-ANA-08-02-01","PAT-ANA-07-01-01"],"correct_rate":0.03}
{"problem":"2023-09모평-30","nodes":["SKL-ANA-08-02-01"]}
```

### 태깅 규칙 — 결정적인 것만

> **문제에는 "그 문제를 푸는 데 결정적이었던 노드"만 답니다.**
> **전제로 깔린 기초 개념은 달지 않습니다. 선수관계를 거슬러 올라가면 자동으로 나옵니다.**

자연수·사칙연산이 모든 문제에 들어간다는 사실은, 그 노드가 거의 모든 노드의 **조상**이라는
형태로 이미 온톨로지에 표현되어 있습니다. 다시 적을 필요가 없습니다.

덕분에 문제당 태그가 2~4개로 유지되어 **AI 가 태깅해도 사람이 검수할 수 있습니다.**

## 10. v1 → v2 이관

기존 571개에 대해 **자동으로** 처리합니다. 사람이 손댈 것은 없습니다.

| 작업 | 방법 |
|---|---|
| `type: concept` 추가 | 전부 동일 |
| `core_concepts` → `definition` | 키 이름만 변경 |
| 빈 3개 섹션 삭제 | 전부 플레이스홀더라 손실 없음 |
| `display_order` 부여 | 현재 폴더 순서 × 10 |
| `grade` / `course` | **비워둠**. 나중에 채움 (지금 추측하면 틀림) |
| `status: draft` | 전부 동일 |
| `source: ai` | 전부 동일 |
| 중복 선수관계 459개 | `restructure.js --dedupe` 로 제거 |

`level: 세분류` 는 `type` 이 대신하므로 제거합니다.
