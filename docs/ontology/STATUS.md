## ⚠️ 반드시 알아야 할 사실

### 1. `practical_concepts` / `action_guidelines` / `misconceptions` 는 "빈" 게 아닙니다

플레이스홀더 문구(`[2~3단계에서 작성 예정]`)가 앞에 붙어 있어 처음엔 0% 로 보였지만,
**제목·본문 안에 실제 내용이 이미 쓰여 있습니다.**

571개 전수 실측 (같은 문장이 5회 이상 반복되면 "껍데기"로 계산):

| 필드 | 고유 원고 | 복붙 껍데기 | 원고 글자수 |
|---|---:|---:|---:|
| `action_guidelines.action` | 571 | 0 | 94,602 |
| `misconceptions.title` | 571 | 0 | 57,192 |
| `practical_concepts.title` | 471 | 100 | 49,401 |
| `action_guidelines.title` | 472 | 99 | 46,762 |
| `action_guidelines.situation` | 571 | 0 | 29,737 |
| `misconceptions.diagnosis_message` | 91 | 480 | 16,380 |
| `practical_concepts.content` | 89 | 482 | 15,913 |
| `misconceptions.symptom` | **1** | **570** | 26 |
| **합계** | **2,837** | **1,731** | **310,013** |

예시:
> `ALG-02-04-05` — "두 다항식을 x−2로 나눈 나머지가 같을 때" 식을 세우지 않고
> **P(2)=G(2) 로 미정계수를 1초 만에 구하는 스킬**

**이게 목표로 하는 "일타강사 층" 그 자체입니다. 절대 삭제하면 안 됩니다.**
전부 AI 가 생성한 뒤 검수하지 않은 상태이므로 `source: ai`, `status: draft` 로 기록합니다.

**중요:** 보존 대상 2,837건과 삭제 대상 1,731건이 **같은 섹션 안에 섞여 있습니다.**
그래서 삭제는 반드시 **필드 단위**여야 하고, 섹션 단위로 지우면 31만 자가 사라집니다.

또 하나 — 대기 문구가 세 가지 형태입니다. 문자열 검색으로 거르는 설계는 실패합니다.

```
"[2~3단계에서 작성 예정] 실제 원고"     ← 표식만 떼면 원고가 나온다
"…기록 예정. (예고: 실제 원고)"          ← 괄호 안이 원고다 (176건)
"…기록 예정"                             ← 진짜로 내용이 없다
```

### 2. ID 가 폴더 위치에 묶여 있습니다

`ANA-07-03-05` = 해석학 / 중분류07 / 소분류03 / 세분류05.
571개 전부 일치하고 번호에 빈틈이 없습니다.

→ **중간에 중분류를 끼워 넣으면 뒤 ID 수백 개와 선수관계가 전부 깨집니다.**
→ 해법: 폴더 번호를 바꾸지 말고 뒤에 붙이며, 표시 순서는 `display_order` 필드로 제어.
→ 정말 재배치가 필요하면 전용 스크립트(`restructure.js`)로. **손으로 하지 말 것.**

5개 분류 검토 축이 **서로 모르는 채 전부 같은 결론**에 도달했습니다.

### 3. 검수자가 1명(원장)뿐입니다

- 사람이 550개를 전수 검수하는 설계는 실패합니다.
- **AI 가 만들고 AI 가 판단하는 것도 실패합니다.** 같은 실수를 공유합니다.
  (이 프로젝트에서 실제로 검증 에이전트가 162건 중 161건을 그대로 통과시킨 전례)
- → 검수를 **"판단"이 아니라 "실행"** 으로 바꿉니다. 수학은 실행 가능합니다.
  스킬이 적용된다고 태그된 기출을 실제로 그 스킬로 풀어 정답이 나오는지 확인합니다.

| 대분류 | 중분류 |
|---|---|
| 수와 연산 (6) | 자연수·약수배수 / **분수와 소수** / 정수와 유리수 / 유리수와 순환소수 / 제곱근과 실수 / 복소수 |
| 대수 (6) | 비와 비율 / 문자와 식 / **방정식** / 부등식 / 집합과 명제 / 행렬 |
| 해석학 (8) | 대응과 좌표 / 함수의 기초 / 대수함수 / 초월함수 / 수열 / 극한과 연속 / **미분** / 적분 |
| 기하 (7) | 초등 도형 / 논증기하 / 입체도형 / **도형의 방정식** / 이차곡선 / 공간도형·좌표 / 벡터 |
| 확률과 통계 (6) | 자료의 정리 / 대푯값·산포도 / 경우의 수·순열조합 / 확률 / 확률분포 / 통계적 추정 |

"확정"은 **영원히 고정이 아니라 이번 라운드의 기준선**입니다.
재구성 스크립트가 있으면 나중에 바꿀 수 있고, 그래야 계속 발전합니다.

### ② 스키마 v2 — 노드 4종 + 관계 6종

상세: `docs/ontology/SCHEMA_v2_draft.md` — 적대적 검증 71건을 반영해 1·2·3·9·10장 개정 완료.

ID 규칙이 초안에서 바뀌었습니다. skill/pattern/trap 은 **개념 좌표를 빌리지 않고
일련번호**를 씁니다(`SKL-0001`, `_skills/` 폴더). 좌표를 쓰면 한 개념에 스킬이 둘일 때
곧바로 ID 가 충돌합니다 — `ANA-08-03-05` 하나에 사인치환·탄젠트치환이 이미 들어 있습니다.

```
concept  개념   definition / properties
skill    스킬   trigger_signals / procedure / why_it_works / limits
pattern  유형   recognition / required_skills / typical_traps / time_budget
trap     함정   symptom / why / diagnosis_message / correction
```

관계: `prerequisite` `applies_to` `combines` `alternative_to` `faster_than` `trap_of`

`faster_than` 이 중요합니다 — **수능 고득점은 "풀 수 있나"가 아니라 "제한 시간에 푸나"** 입니다.

### ③ 기출 증거는 노드에 넣지 않습니다

`evidence` 필드 **없음**. 이유:

- 개념 노드는 태그 대상이 아님 — "자연수의 사칙연산"은 모든 문제에 들어가 정보량 0
- 목록이 무한히 자라 사람이 검수할 수 없게 됨

대신 **분리**합니다.

```
온톨로지 YAML        지식 구조. 안정적. 사람이 검수.
      ↕ 참조만
tags/problems.jsonl  관측 데이터. 계속 쌓임. 기계가 처리.
      ↓ 빌드가 집계
build.json 의 stats  "이 스킬 47회 출제, 평균 정답률 31%"
```

**태깅 규칙:** 문제에는 *결정적이었던 노드만* 답니다. 기초 개념은 선수관계를 거슬러
올라가면 자동으로 나오므로 적지 않습니다. → 문제당 태그 2~4개 유지 → 검수 가능.

### ④ 기준 문서

- **성취기준**: 기준이 아니라 **커버리지 체크리스트**로만. 고득점 스킬이 전무하므로.
- **진짜 기준은 기출**: 실제로 무엇이 요구되었는지에 대한 유일한 검증 가능 증거.
- **일타강사 층은 공개 문서가 없음** → 기준을 "문서"가 아니라 **"프로세스"** 로 만든다.

### 검증에서 나온 것 중 아직 안 고친 실제 데이터 결함

전부 데이터 레포 `scripts/validation-baseline.json` 에 등록되어 경고로 추적 중 (새 위반만 ❌).

| `ALG-02-06-03` 이 `ALG-02-06-01` 의 통째 복제본 | 제목상 있어야 할 "부분분수" 개념이 실제로 없음 |

`restructure.js` 는 아직 존재하지 않습니다. 초안이 이 도구를 전제로 쓰였으나 실물이 없습니다.

### 브랜치 보호 — 안 걸기로 결정 (2026-08-10, 근거 실측)

시도 결과 두 가지가 확인되어 **ruleset 을 만들지 않기로** 했습니다:

1. **개인 계정 비공개 레포는 ruleset 이 집행되지 않는다.** 설정 화면에 경고가 명시됨
   ("won't be enforced ... until you move to GitHub Team organization account").
2. **내장 `github-actions` 앱을 bypass 목록에 추가할 수 없다** (Apps 탭에 설치형 앱만 표시).
   지금 Active 로 저장해 두면, 나중에 Team 조직으로 이전하는 순간 규칙이 살아나며
   bypass 없는 bot 의 build.json 자동 커밋이 소리 없이 거부되기 시작한다 — 잠복 지뢰.

**실질 방어 (현재 동작 중):** PR 마다 검증 CI 가 ❌/✅ 를 표시하고(PR #1 실증),
머지 권한자는 원장 1명뿐이며, AI 도 CI 초록 확인 후에만 머지를 요청한다.
빨간 PR 은 머지하지 않는다 — 이것이 규율이다.

**강제 차단이 필요해지면:** GitHub Team 조직 이전(유료) + 그 시점에 bot 푸시를
원장 PAT(secret) 방식으로 교체해야 한다(checkout 의 token 교체, 워크플로 한 줄).

### 검증기의 알려진 한계 (의도된 범위 밖)

- 규칙 14는 정규화 후 **완전 일치**만 잡습니다. 한 글자 바꾼 근사 복제, 의미 단위 중복은 못 잡습니다 — 이관 절차(0-11)와 표본 검수가 담당합니다.
- 규칙 6의 skill/pattern/trap 위치 검사는 문서 9장보다 엄격합니다(전용 폴더 직속 강제). 문서 쪽을 이에 맞게 고칠 것.
- 규칙 13 보조규칙(같은 영역 번호 순서)은 두 노드의 학년이 다르면 건너뜁니다. "새 중분류 뒤에 붙이기"가 실제로 일어나 같은 학년 안에서 정당한 역전이 생기면 `display_order` 비교로 교체할 것.
